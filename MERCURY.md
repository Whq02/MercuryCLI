# MERCURY.md
Standing orders for the Mercury harness in this repository.

- The operator's word names the model for every lane, seat and review. No model is paired with a kind of work by default and none is off limits; a project file never outranks what the operator says, and a conflict between the two is asked, never settled alone.
- A minor look change (a row's words, a count, a clamp clause, a notice) lands on its source-render frames without the owner's approval; only a big design change — the outline, the format, the design orientation, animation or rendering presentation — stops at frames for the owner before it lands.
- Jev (JevEval) is a general judge, not a writer, and stays one: a session hands it any text — a paragraph, named facts, or a list of them — plus closed questions (yes/no with a probability, a pick from options, a position on a scale) and gets one table back; nothing in it knows about reds, docs or drives; the only product work on it is more input shapes (a file, a list, a pair, a table) so a session need not paste every item, and nothing is wired into the harness to run on its own. On our own development it runs as lanes after the tag — a stale-law census (every prover check beside the product line it reads), a stale-comment census, docs against the product on every release, the hosted Linux reds triaged with the hosted log beside the local green, and lane reports against receipts before every fold — under these rules: only closed questions whose answer is in the text; never a verdict from a bare log, rerun the red alone first and hand Jev the whole picture (what the check expected, what the screen showed, what changed, the load, the rerun); unsure stays unsure, never flake; no Jev where a grep or a rerun already answers it; one packager (the red road's shape) turns each job into evidence plus a question set; do not overdo it where it is not helping.
