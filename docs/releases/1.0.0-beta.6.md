# 1.0.0-beta.6 — in progress

**State:** the next tag of the public line. Its changes land on the day-to-day
line and are listed under 1.0.0-beta.6 in the release notes the product shows;
this page names the headline items and what stays queued. The verdict, the
tag commit and the publish line are written at the tag.

**Planned for this tag — Mercury measured.** A head-to-head on one model and
sixteen tasks put Mercury level with two other harnesses on what got done and
behind on what it cost: more turns, more tokens carried per call, more time.
This tag ships the fixes that need no benchmark rig, each capability-neutral
(nothing removed, nothing degraded) and each checked by a small local
measurement before and after; the release notes state the numbers.

1. **Idle cost** — the cockpit's tickers (the animated title, the clock, the
   glyph animation, the companions) slow after a few quiet seconds and stop
   when the terminal loses focus, resuming on input or a turn. Measured: the
   CPU of an idle cockpit over five minutes.
2. **The process fleet** — no background worker before something needs it,
   idle workers reaped after a quiet period, a cap, respawn on demand.
   Measured: the resident memory of every Mercury process at rest and thirty
   minutes after the last prompt.
3. **The weight around every call** — rarely needed tools ride behind the tool
   search instead of every call, prompt sections lose repeated and dead text,
   unchanged attachments are not re-sent. Measured: the input tokens of the
   first call of a fixed prompt.
4. **More than one tool per message** — independent read-only calls in one
   message run concurrently, and the prompt says batching is welcome.
   Measured: tools per message on a fixed multi-file task.
5. **The frame stall and the slow cold boot** — synchronous process spawns off
   the drawing path, boot probes with short deadlines. Measured: the boot
   milestones and the frame times.
6. **Tool failures** — the failure rate read from Mercury's own transcripts and
   fixed at its causes; a tool description never names a tool the session does
   not offer.
7. The fixes that ride along: a Windows session whose preserved thinking was
   dropped while sub-agents ran.

**Still queued, not this tag:** a local benchmark rig in the repository
(sixteen fixed tasks with hidden verifiers, run headless in fresh workspaces on
one model, one table) and the deeper per-call context cut it will measure; the
seat ceiling as a setting; Linux arm64 and Windows arm64 archives; the adviser
tool; multiplayer; the design-tool bridges; the response-length choice; the
vendored shell.
