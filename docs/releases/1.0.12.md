# 1.0.12 — queued

**State:** queued behind 1.0.11.

## What changed

- Added GPT-6.2 Astra and GPT-6.2 Sol to the model picker with their windows,
  output ceilings and prices from OpenAI's pages of 17 November: Astra at $8 a
  million input tokens, $40 output, $0.40 cached and $10 cache write, Sol at
  $2, $10, $0.10 and $2.50; a request over 272,000 input tokens at twice the
  input and cache rates and one and a half times the output rate. With an
  OpenAI API key the effort dial runs from low to max on both, and Mercury
  sends medium when none is chosen; a ChatGPT sign-in's own list decides its
  levels. An unlisted model had run on a 200,000-token fallback and its usage
  went unpriced. Both are also on OpenCode Zen and in the head rows of the
  Nous Portal list.
- Added a debug-log line on the OpenAI road that lists the input items the
  provider reports it withheld from a request, by type, with the reason for
  each. The line names the first 32 items and counts the eight commonest
  types, actions and reasons by name, summing the rest.
- Added GNU bash to what a macOS or Linux archive carries, under the GNU
  General Public License, version 3 or later: Mercury starts it as a separate
  program, and its licence text and a note naming its source ride beside the
  binary at `vendor/bash/<platform>/`.
- Added GNU bash 5.3.20 to what a Windows archive carries, as the MSYS2
  project packages it, with the MSYS2 runtime and the programs a command
  names (`ls`, `cat`, `grep`, `sed`, `find` and the like): nineteen packages,
  23 MB in an installed version, under the GNU General Public License,
  version 3 or later, and the licences of the other packages. Mercury starts
  each program as a separate program; the licence texts and a note naming
  where each binary and source package is ride beside them at
  `vendor/bash/<platform>/`. Windows on Arm runs the same x86_64 programs.
- Added `models` to the `close` row of a `mercury runner` session: the model
  calls that wrote the note for the next session, by model, each with its
  `cost_usd` where the model has a price. The note's cost stands on that row
  and in no `outcome`, whether the host closes its end while a turn is
  running or after one. The published SDKs (0.2.0) already name the field.
- Changed the model a new session starts on after an OpenAI sign-in: the Sol
  of the newest GPT release the account serves, so GPT-6.2 Sol where it
  serves it and GPT-6.1 Sol, as before, where it serves neither 6.2 model.
  Where the account serves a release and not its Sol the session starts on
  that release's first model in Mercury's list, GPT-6.2 Astra where it serves
  Astra and not Sol, and on the account's own first model only where it
  serves none Mercury knows. Astra is in the picker beside the default.
- Changed the default so that a specialised or premium model is never the one
  a new session starts on while the account serves a general one: an account
  with GPT-5.5 and GPT-5.6 Cyber starts on GPT-5.5, one with GPT-5.4 and
  GPT-5.5 Pro on GPT-5.4. An account that serves only such models starts on
  its own first one, and the picker lists every model as before.
- Changed the default so that a deprecated model is never the one a new
  session starts on while the account serves another that Mercury knows:
  GPT-5.4 nano, which OpenAI's page marks deprecated, is passed over. An
  account that serves it alone starts on its own first model.
- Changed the head rows of the Nous Portal list: GPT-6.2 Astra and GPT-6.2
  Sol take the place of GPT-6.1 Sol.
- Changed the OpenAI lines of /caching to today's facts: a 30-minute lifetime
  by default with 12 hours on offer and not asked for, and cached input at
  0.05 times the uncached rate on GPT-6.1 and GPT-6.2.
- Changed when a session compacts on GPT-5.6 Sol, Terra and Luna, GPT-6
  Astra, Sol and Luna, and GPT-6.1 Sol and Terra with an OpenAI API key, on
  OpenCode Zen and on the Nous Portal: at 879,000 tokens, before the
  922,000-token input maximum OpenAI's pages state, where it compacted at
  1,007,000; the two GPT-6.2 models compact there too. A window that a
  ChatGPT sign-in's list states decides as before.
- Changed what a context window stated in your own settings does on those
  models: the gauge shows the window you state, and compaction still starts
  at 879,000 tokens, before the model's 922,000-token input maximum, where
  a stated window of 1,050,000 compacted at 1,007,000.
- Changed when a session compacts on GPT 5.5 and GPT 5.4 through OpenCode
  Zen: at 879,000 tokens, before the 922,000-token input maximum models.dev
  states for them, where it compacted at 1,007,000. With an OpenAI API key
  the two compact at 1,007,000 as before: OpenAI's pages state no maximum.
- Changed when a session compacts on GPT-5.6 Cyber, GPT-5.4 mini and GPT-5.4
  nano with an OpenAI API key, and on GPT-5.4 mini and nano on the Nous
  Portal: at 229,000 tokens, before the 272,000-token input maximum their
  pages state, where it compacted at 357,000. The gauge names their
  400,000-token window as before.
- Changed what the context gauge shows on those models: it names the
  1,050,000-token window as before, and the share left until compaction is a
  share of that window, 36% at 500,000 tokens where it read 48%.
- Changed three messages on those models to say what their number is: the
  size warning after a failed request, the note shown when you switch model
  and the line printed when a provider refuses a request for its size name
  the model's 922,000-token input limit, where they named its
  1,050,000-token window.
- Changed the cost shown for GPT-5.6 Sol to follow the date its promotional
  price ends: $4 a million input tokens and $20 output through 30 November
  2026, and from 1 December $5 and $30, the prices its page's stated
  reductions of 20% and 33% start from, with cache writes at $6.25.
- Changed the shell the Bash tool runs on macOS and Linux: Mercury ships GNU
  bash 5.3.20 and runs every command in it, whatever your login shell is. On a
  Mac whose login shell is zsh the model's bash commands had run in zsh. When
  the shipped bash cannot start, the system's own bash runs the command, and
  with no bash at all the bundled engine does. The Bash tool never runs a
  command in zsh and never hands one to it: an editor's terminal is asked to
  start Mercury's shell on the command, and an editor that cannot start it is
  passed over for the session, the command runs locally and the first result
  says so; a `MERCURY_SHELL_PREFIX` wrapper is handed one line, every word of
  it quoted, so whichever shell the wrapper runs reads no word of the command.
  That line starts Mercury's shell where its path can be run and, where it
  cannot (the wrapper went into a container or to another host), the `bash`
  found there; with no bash there the command fails and says so. A hook under
  the wrapper is handed one quoted line too, which starts `/bin/sh` on the
  hook, where the wrapper's own shell had read the hook's words.
- Changed what a command starts from on macOS and Linux: the environment
  Mercury was started with, `PATH`, `SHELL` and every exported variable,
  reaches each command unchanged, from a terminal, the daemon or an editor
  (`$BASH` names the shell that runs; `$SHELL` is still your own, so a
  program that starts `$SHELL` itself, as an editor's `!` command does,
  starts your own shell). No command
  is a login shell: your bash login files are read once a session, in one
  login run with no input and ten seconds to finish, begun as the process
  that runs the session starts, before it takes its tool list (its first
  request waits for it and nothing else does), and the
  aliases,
  functions and options they define are carried to each command, from
  `~/.bash_profile` (or `~/.bash_login`, or `~/.profile`) and from `~/.bashrc`,
  whether or not `~/.bashrc` exists. Every function is carried, whatever its
  name, and an alias under `set -o posix` too. One option is not: `extglob`
  is off when a command starts, because Mercury reads a command's words
  without it, so a function whose patterns need it switches it on in its own
  body. What the files export, and a `PATH` they set, is not carried either:
  a command starts from the environment Mercury was started with. A
  `~/.bashrc` that returns early for a
  shell that is not interactive, as Ubuntu's does in its first lines, carries
  nothing written below that line: put what a command needs above it or in
  the login file. A login file that ends the shell, hands it to another one
  or runs past the ten seconds carries nothing, and commands still run. Such
  a session says so: the first result of the Bash tool has one line with the
  reason and what to change, and the Bash tool's description does not say a
  call starts from your profile. If your login file hands the shell over to
  zsh (`exec zsh -l`), hand it over only in an interactive shell
  (`case $- in *i*) exec zsh -l ;; esac`) and what the file defines is carried.
  Aliases and functions written in `~/.zshrc` no longer reach a command, and a
  variable set in `~/.zshenv` reaches one only when the program that started
  Mercury already had it.
- Changed the session's shell line on macOS and Linux to name the shell that
  runs and its version, where it named your login shell; on a system bash
  older than 4.0 the line also says how to hand over a message of several
  lines.
- Changed three questions the Bash tool asked before running a command: a
  command that holds `~[`, a word that begins with `=`, or the name of a zsh
  module builtin such as `zmodload` is read like any other, since bash gives
  none of them a meaning of its own. A command that starts zsh itself
  (`zsh -c '…'`) is asked about as a program whose script Mercury does not
  read, where that script was read as if bash would run it.
- Changed the shell the Bash tool runs on Windows: a bash 5 that is installed
  serves first (Git for Windows ships one), a machine with none, or with one
  older than 5, runs the bash Mercury ships, and the bundled engine serves
  only when no bash starts or when you choose it. The bundled engine had been
  the default on Windows; `MERCURY_SHELL_ENGINE=brush`, or `brush` in
  `/config` under Shell engine, keeps it. On Windows too Mercury runs no
  command of the Bash tool in zsh; a `MERCURY_SHELL_PREFIX` wrapper there is
  handed the command's line itself, as before, so the shell that wrapper
  starts is the one that reads it.
- Changed what `MERCURY_SHELL_ENGINE=system` means on Windows: a bash and
  never the engine. With no installed bash 5 the bash Mercury ships serves,
  where the Bash tool had left the tool list.
- Changed `MERCURY_GIT_BASH_PATH`: the program it names serves before any
  other when it answers as a bash, whatever its version; one that does not
  is passed over, where it had been run as the shell. The first Bash call of
  the session tells you once why and which shell serves instead, and the
  health check names it. From then on `SHELL` in the environment Mercury
  hands to a hook or to any other program it starts names the shell that
  serves.
- Changed the session's shell line on Windows to name the shell that runs and
  its version, where it named the word in `SHELL`.
- Changed the health check's Bash tool shell row on every platform: it names
  the shell that runs, its version and where it came from, lists what was
  passed over and why, and warns when the install carries no bash pack or
  when the bundled engine is the last shell left. On macOS and Linux it also
  warns when nothing of your bash login files is carried, with the reason and
  what to change. The Bash tool shell row of `/capabilities` says the same
  words and the same fix once a session has settled on a shell.
- Changed what a tool call that was cut before it began leaves in the trace:
  no line in `mercury-trace.jsonl`, where it left one marked failed for a
  tool that never ran. A call cut after its hooks or its permission question
  ran is recorded as before.
- Changed two answers on the runner's wire from the internal error `-32603`
  to the refusal `-32010`, with the sentence they carried: `project/query` in
  a folder nobody trusted (`error.data.kind` is `trust`, a new kind) and
  `agent/resume` for a crewmate nothing recorded (`agent`). Both SDKs raise
  a `MercuryRefusal` for them, where they raised the error a fault raises.
- Changed `mercury run` started with `MERCURY_CONCOURSE_WORKER=1` and no
  session named: it ends at once with exit 2 and one sentence on stderr,
  which says that it waits for a claim only `mercury runner` can take and
  how to name a session. It had started no turn and ended with exit 1,
  saying `The run produced no outcome` on stderr in the text format, in a
  failed outcome row in the json format, and nothing in the rows format.
- Changed more answers of `project/query` on the runner's wire from the
  internal error `-32603`. A parameter that is missing or malformed
  (`session_id`, `sender`, `message`, `query`, `ref`) answers `-32602` in the
  form of every other `-32602` of the wire, with
  `invalid params for project/query` as the message and the sentence it
  carried under `error.data.issues` beside the parameter's name; so does a
  `message` the daemon refuses for its size, with the daemon's sentence. Both
  SDKs keep that on the `data` of the error they raise, and Mercury's MCP
  server prints the sentence after the message. A session that is not saved
  or not live, a session of another project, a message the daemon does not
  take and a file the read rules do not allow or that lies outside the
  project answer the refusal `-32010` with the sentence they carried; their
  `error.data.kind` is `project`, a new kind.
- Changed the code a caller of the daemon's socket reads when the reply
  cannot be read: `EBADMSG`, where a reply that is no JSON carried `EUNKNOWN`,
  the code of the daemon's own refusals, and a reply past the size cap, read
  by a daemon forwarding to the one before it, carried `ETOOLARGE`. It is a
  fault on the caller's side, and `project/query` on the runner's wire
  answers it as the internal error `-32603`, never as a refusal.
- Changed the health check's execution census row: it counts one domain
  fewer among the domains with hooks, 3 on a fresh start where it read 4.
  The language-server domain registered a hook that nothing called, and no
  longer registers one; a language server's run is recorded as before.
- Changed what a model reads about the Computer tool when it looks the tool
  up: the tool's line names what it needs, a desktop driver that resolves,
  where it read as available. The tool runs as before.
- Fixed the effort dial on GPT-6 Astra, Sol and Luna and GPT-5.6 Sol, Terra
  and Luna with an OpenAI API key: the level chosen is sent, where nothing
  was sent and the provider's default ran. When none is chosen Mercury sends
  medium: the default their pages state, and on GPT-6 Astra, whose page
  names none, the default OpenAI's API reference gives for the setting.
- Fixed the id of GPT-5.5 Cyber: the picker and the price table name
  `gpt-5.5-cyber-preview`, the id OpenAI's pricing page lists, where they
  named `gpt-5.5-cyber`, an id no OpenAI page lists.
- Fixed the cost shown for OpenCode Zen models with a long-context tier: a
  cache write past the threshold is priced at the long-context rate ($25 a
  million on GPT 6 Astra where it read $12.50), and a request of exactly
  272,000 tokens (200,000 on Grok) at the short rate.
- Fixed finding the `bash.exe` of a Git for Windows whose `git.exe` is on
  PATH from its `ucrt64`, `clang64` or `clangarm64` folder.
- Fixed a first command that never started when the program asked for its
  bash version ignored the request to end: the question ends after five
  seconds and the program is ended.
- Fixed the bash version a session names when `BASH_ENV` names a file that
  prints: the version is asked without that file.
- Fixed a session on Windows that offered a Bash tool no call of which could
  run, and said nothing to you: when no bash starts and the bundled engine
  does not serve, the first Bash call tells you once which programs were
  passed over and why, and what to do (install Git for Windows, set
  `MERCURY_GIT_BASH_PATH` to a `bash.exe`, or reinstall Mercury; then restart
  Mercury). The model is told in one line that Bash cannot run in the session.
- Fixed the bundled engine refusing every command while `BASH_ENV` is set in
  the environment Mercury was started from: the engine starts without it, so
  a command under the engine does not see `BASH_ENV`. `ENV` never stopped
  the engine and reaches such a command as you set it.
- Fixed a stray line after every command under a `MERCURY_SHELL_PREFIX`
  wrapper that runs the command where Mercury's temp folder is not (a
  container, another host): `No such file or directory` for a file of
  Mercury's own. The command's output and exit are its own; the working
  folder such a command moves to is not carried to the next one.
- Fixed the bundled engine carrying nothing of `~/.profile`: its login run
  was started with flags in an order the engine refuses. The aliases,
  functions and options `~/.profile` defines are carried into an engine
  session, with job control off as in bash.
- Fixed a command run a second time in the local shell when an editor took
  more than thirty seconds to answer the request for a terminal: the result
  is an error that says the command may be running in the editor's terminal.
- Fixed output lost or cut without a word in an editor's terminal: output
  that reaches the terminal after the command has ended is waited for, three
  seconds at most, and the result says when the output was still growing
  then and when the editor truncated it.
- Fixed the cost shown for Nous Portal models whose list states a
  long-context price: a request at or above the list's threshold is priced
  at the list's long-context rates, where every size read the short ones
  (GPT-6.2 Astra from 272,000 input tokens: $16 a million input, $60 output,
  $0.80 cached and $20 cache write, where it read $8, $40, $0.40 and $10).
- Fixed a change of permission mode being recorded twice in the window's own
  process: it is recorded once, on the road that made it, where a second row
  that named no road followed each change and the debug log held two lines
  for it.
- Fixed a seat that stayed taken after a run was ended between taking it for
  a model request and sending the request, as a run stopped at the notice
  that follows a model switch could be: the seat is given back as the run
  ends, where it stayed taken until the session's process ended, each one
  leaving the session a seat short, and with none left every later request
  waited (a crewmate's row read `waiting for a seat`).
- Fixed the model a chat names after `/model` picks the session's own
  setting while another model is serving it, a fallback for one: the chat
  goes on naming the model that serves, where it named the setting until the
  session next reported its state.
- Fixed the setup of a Vast.ai instance that refuses Mercury's SSH key when
  the wait for SSH ends during a read of the instance's status: the key was
  not attached to the instance and the setup paused there. The key is now
  attached and SSH tried again however that wait ends, and a pause after a
  second refusal says the key was attached and retried, where it left that
  out.
- Fixed a host setup that stopped with `Could not read the host SSH public
  key.`, or went on with an SSH key that was never attached, when the machine
  was busy: the output of a command Mercury ran for it (`ssh-keygen`, `ssh`)
  was taken when the command exited, and what had not been read by then was
  lost. Mercury now reads the output to its end, waiting at most two seconds
  after the exit when a process the command started keeps it open.
- Fixed an account change that reached a session while its runner was still
  starting: the runner takes it once it has started, where a runner that was
  resuming a session dropped it and went on with the account it had read. On
  the runner's wire, a notification sent before `initialize` is answered
  waits for that answer, as a request does.
- Fixed the totals of a turn's `outcome` on a `mercury runner` session when
  the host closes its end while the turn is running: `usage`, `cost_usd`,
  `api_ms` and `models` count the turn's own model calls, where they also
  counted the calls that wrote the note for the next session. The `close`
  row before that `outcome` carries the note's `usage`, as it did, so a
  client that adds every `outcome` and the `close` row counts each call once.
- Fixed a crew chat panel, and the crew view of a hosted session, that could
  stay behind until the next post when the file event for a post was lost,
  as macOS loses one while another folder starts or stops being watched: the
  board is read again within two seconds.
