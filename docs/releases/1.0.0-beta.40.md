# 1.0.0-beta.40 — ready for the tag

**State:** ready for the tag. `/llmhost` opens on models first, showing where
each model can run right now: on a running pod, on your own computer (`mercury
host`), or on a GPU rented from Runpod, Vast.ai or Lambda, with quality,
conversations × context and thinking shown in plain words. You can keep model
weights on a Runpod fast-load volume, tune quality, context splits and thinking
before renting or on a running pod, and set reasoning levels with `/effort` on
self-hosted and OpenAI-compatible servers. Trillion-parameter recipes (`Kimi
K3`, `Qwen3.8-2.4T-A95B`, `DeepSeek V4 Pro`, `MiMo-V2.6-Pro-RL`, `Mistral Large
3 675B`, `GLM-5.3`) support single-node and multi-node Runpod Instant Clusters
with full hourly compute, storage and download disclosures, and `llama.cpp`
GGUF rentals start from a prebuilt CUDA 13 engine image. Running `!` shell
commands stream a live output tail in chat, `/mcp` signs in and browses server
tools and schemas in place, and `/restart` switches a live chat onto a newly
installed Mercury build.

## What changed

- Added model-first `/llmhost` and `/model` hosting actions: `/llmhost` opens
  on `Which model?`, showing where each model can run right now, its quality
  variants, its GPU-memory budget split across parallel conversations
  (`conversations × context`) and its thinking level, while `/model` includes
  searchable `run it → /llmhost` actions (`run it on this Mac →` when a model
  fits a local Mac)
- Added GPU rentals across Runpod, Vast.ai and Lambda in `/llmhost`: Runpod
  rentals, background setup workers and 5-second stock watches are joined by
  Vast.ai and Lambda rental adapters, which are new and verified against the
  vendors' published APIs on fixtures (live rental runs were not performed)
- Added own-computer model servers (`/llmhost` → `My computers` and `mercury
  host start|status|stop|restart|logs|uninstall|add|recipes`): inspects this
  computer or a saved SSH computer, selects a memory-fitting Ollama or GGUF
  recipe, verifies a local `SHA256SUMS` weight bank or confirms a download, and
  runs the engine as a user login service (`launchd`, `systemd --user` or
  Windows Scheduled Task) registered as `compat/box-<name>/<model>`
- Added fast-load kept weights disks in `/llmhost` (`Fast-load (keep weights
  near the GPU)`): stores revision-verified model weights on a Runpod network
  volume or global volume (`Prepare now` or `At the next rental`), checks warm
  mounts by seeded sampling in seconds (with full SHA-256 verification on
  demand), and shows monthly storage billing and keep-or-delete choices when
  terminating a pod
- Added `Tune` before renting and on a running pod in `/llmhost`: chooses
  quality, `conversations × context` splits against the visible GPU-memory
  budget and default thinking level before confirming a rental, and reloads a
  running `llama.cpp` Runpod pod in place with automatic rollback if the reload
  fails
- Added `/effort` for self-hosted and OpenAI-compatible models: lists and sends
  each model's supported reasoning levels (`chat_template_kwargs` on
  `llama.cpp`, top-level `reasoning_effort` on `vLLM`, `SGLang`, `Ollama` and
  `Kimi K3`), with a one-retry fallback if a server rejects the field with HTTP
  400
- Added trillion-parameter recipes and multi-node Runpod Instant Clusters in
  `/llmhost`: 19 documented recipes across `Kimi K3`, `Qwen3.8-2.4T-A95B` (FP8
  and NVFP4), `DeepSeek V4 Pro`, `MiMo-V2.6-Pro-RL`, `Mistral Large 3 675B` and
  `GLM-5.3` (FP8 and BF16), with full compute, per-node disk, weight-download
  and model-licence disclosures and exact `Kimi K3` assistant reasoning and
  tool-call replay
- Added prebuilt CUDA 13 `llama.cpp` engine image
  (`ghcr.io/whq02/mercury-llamacpp`): `GLM-5.3-Flash` and `Nemotron 3.5 Super
  VL 120B` GGUF rentals detect the preinstalled server and skip source
  compilation during pod setup
- Added live output tail for running `!` shell commands in chat: displays a
  ticking `running · …` clock and the latest output lines (six at 120 columns,
  three at 80) with carriage-return progress updates kept on one line
- Added `/restart` and one-time installed-build notices: a live chat notifies
  once between turns when another Mercury build is installed, and `/restart`
  lists the `Monitor` watches and background shells that will stop, moves the
  background daemon to the installed build and resumes the chat on it
- Added oculus and headless session kinds: sessions started from a screen run
  as `oculus` (permission asks and questions wait for the screen without
  expiry) while unattended `mercury run`, `mercury runner`, scheduled and
  coordinator sessions run as `headless` (`/health` reports `Session kind` and
  the Session Concourse marks `headless` rows)
- Added connected server `tools` list and tool-schema detail view in `/mcp`:
  unfolding a connected MCP server opens a filterable tool list and per-tool
  parameter schema view with `Esc` stepping back one level at a time
- Changed headless runs that ask the user a question nobody can answer to end
  `blocked` with the question quoted on the outcome row, read from the run's
  own asks
- Changed self-hosted `llama.cpp`, `vLLM`, `SGLang`, `Ollama` and `LM Studio`
  streaming: `llama.cpp` conversations attach to a consistent server slot
  (`id_slot` with `cache_prompt: true`), self-hosted dialects check server
  liveness during long prompt prefills instead of cutting after 30 seconds, and
  streaming tool-call arguments count as live crewmate progress
- Fixed daemon-hosted chats dropping post-compaction messages after `/compact`:
  the transcript writer scans every recorded ID on disk without re-appending
  earlier history, and the screen keeps every post-compaction row in order
  across reattach, `/restart` and daemon restart
- Fixed unreachable custom endpoints in `/model` opening an unrelated sign-in
  screen: keyless endpoints retry in place, unreachable custom endpoints show
  `Retry this server →` and `Remove this endpoint →` in `/model`, terminating a
  pod removes its provider registration, and opening `/llmhost` sweeps
  endpoints whose pods have ended
- Fixed `/restart` waiting on its own session during daemon handover, repeating
  on an already-current session, or advising `esc` during a running turn: stops
  the session's runner before handover, reads the runner's build facts first,
  and advises waiting for the running turn to finish
- Fixed the installed-build notice repeating after `/clear` or rendering
  collapsed: `/clear` inherits the shown-build mark from the previous chat, and
  the notice paints unfolded in full
- Fixed `Monitor` watches waking the model on every 1-second tick: after the
  initial 200 ms burst, ongoing output batches at most once every 30 seconds
  with the line count and last line
- Fixed Windows `Monitor`, `run_in_background` and `inherit_session_env` calls
  under the default shell engine: uses located Git Bash when installed and
  spawns per-command `brush` engine processes on Windows machines without
  `bash.exe`
- Fixed `/mcp` sign-in and mid-session server additions: pressing `↵` on a
  `needs sign-in` row runs the authentication flow from the focused runner, and
  MCP servers added at user scope join the running session immediately
- Fixed sessions resumed after a redeploy replaying stale tool schemas: a
  restored tool definition whose live `input_schema` or build tree moved sends
  the live tool schema on both Anthropic and OpenAI Responses requests
- Fixed compaction landing room and session startup probes: compaction reserves
  the largest token underestimate measured in the session so a file-heavy task
  does not compact again on the next round, keyless named endpoints
  (`compat/<name>/<model>`) start new and `/clear` sessions when saved as the
  default model, the full-slots message on the home screen leads with how to
  free a slot (`/concourse` or `/seats N`), and a project nested inside a
  repository at your home directory scopes its startup git status check to the
  launch folder
