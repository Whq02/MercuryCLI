# 1.0.0-beta.17 — queued

**State:** queued behind 1.0.0-beta.16. The plan agreed during the 1.0.0-beta.16 release
puts the six screen designs approved on 2026-09-21 in 1.0.0-beta.17: the
small critter, the file tree menu, centred first-run cards, default model
and effort for new sessions, the small-screen bottom row, and shift+B for
running commands. This release also includes the visible fixes and two
under-the-hood fixes below. The crew-agent view moves to 1.0.0-beta.18.

1.0.0-beta.18 will focus on reliability by running Mercury on every
supported provider, on a machine that can handle the load. Each model will
work on its own sign-in and account handling in a dedicated sandbox. All
of that work must be treated as untrusted and verified. This tests
multi-account use on complex work in Mercury's own codebase, with fixes
addressing the root causes.

1.0.0-beta.19 will preserve the live runner across daemon restarts (item
22). 1.0.0-beta.20 will add image generation as a tool, or finish the rest
of this page first. 1.0.0-beta.30 is the release candidate for leaving beta.
Grok and Muse will be added where they fit; Perplexity follows after beta.
The rest of this page records what remains from 1.0.0-beta.16.

1. **Grok and Muse as providers**, using live model lists where available
   and dated tables otherwise. Perplexity follows after beta.
2. **Refresh every family's model list in the background** when the picker
   opens with cached rows. OpenAI does this from 1.0.0-beta.16. OpenRouter,
   Gemini, Hugging Face and local rows will use the same changed-only rule.
3. **Show `/cost` immediately during a turn**, as `/status` and `/usage`
   do. Read the focused session's cost figure instead of the process's
   cost tracker.
4. **Fix stopped rows on the crew board.** Pressing r should respawn a
   stopped named teammate. The row currently offers resume but refuses it.
   Notify the main agent when you stop or resume an agent from the board.
   Undo the teammate row's registration if spawning fails because the team
   does not exist, so the row does not stay marked as running.
5. **Show the signed-in account everywhere.** Include the account in the
   transcript's "Login successful" line. Read its organisation during
   in-app sign-in so `/status` retains the organisation name after a
   switch.
6. **Show the effort chip's value from the first frame.** Remove the
   one-second "(asked)" label while the session confirms it.
7. **The compact board's contract offer card** overflows at 80×14 and
   82×17. Clipping hides its question and Yes/No rows.
8. **Handle a daemon exiting just after it answers a new window.** This
   currently costs the window one retry ("daemon closed without a reply").
   Startup could repeat its daemon check once.
9. **Fix two small-screen issues after failover.** At 80 columns, the
   failover sentence is cut off before its "/model to return" instruction.
   At 80×21, the compact composer says the session is landing while the
   band above it already says ready.
10. **Send the cockpit's usage windows and pools to the runner.** This
    reverses 1.0.0-beta.16's relay so the runner's own notice also reads
    the endpoint's record.
11. **Gemini after a real Google sign-in.** When the project's Gemini API
    is disabled, show Google's instructions in the picker row instead of
    "re-connect". Gemini ids outside the routable `gemini-` space,
    including music, agent and deep-research previews, should be routed
    if they support the chat call, or hidden otherwise. Distinguish rows
    that share a display name. For new-session defaults, `m` opens the
    chat's model picker when the concourse's new-session entry is focused,
    or from the Boot face in `--chat`. The entry shows the model and effort
    that new sessions will use. The bottom row says "m to select
    model-default". Remove the picker's "frontier" lines and use the
    default you chose.
12. **The composer when a chat opens; the bottom row on small screens.**
    Keep the caret in place on its first move after opening. At 80 columns,
    keep the back control on the bottom right when a notice appears,
    truncating the notice to fit. New sessions use the saved model and
    effort shown in the concourse's new-session entry.
13. **The file tree menu and small critter.** A FILES box in the left rail
    shows the folder. Clicking it or pressing ↵ opens a tree over the chat,
    like the model picker. Folders expand and collapse, the current file
    is highlighted, changed files show their git status, and `/` filters
    by name. Pressing ↵ on a file inserts its `@path` in the composer and
    closes the menu. esc or a click outside also closes it. The rail stays
    in place. `/critter mini` reduces the session box to the three-row
    sprite used in the 80-column band, giving the chat more rows. It also
    removes the SESSIONS strip under the chat and the roll-up line beside
    the critter. Each change is reversible; `/critter full` restores
    the art.
14. **The workspace trust card can flash briefly at boot** for a trusted
    folder. Seen once and not yet reproduced.
15. **Messages between Mercury sessions** should arrive as notifications,
    as agent messages within a session now do. Sending a message from the
    chat to a crew mate currently fails because it requires a team.
16. **Mercury processes left behind.** A daemon started by a headless run
    with no window outlives the run. A window's process can also remain
    after its parent exits. Daemon startup or the doctor could find and
    end them. On macOS, windows whose terminals have died can hang in a
    kernel wait. Two remained in an uninterruptible wait for three days;
    opening the terminal device put the inspecting process in the same
    state. Investigate where Mercury opens terminal devices and whether
    its windows can encounter this wait.
17. **Write the daemon's supervisor record atomically.** Publish the whole
    record through the substrate's publish interface for boot, owner
    hand-over and the stopping mark. These currently use plain writes.
18. **Three findings from the sanity check.** The first daemon log line
    puts its timestamp at the end. A background sub-agent's tool search
    says it is disabled even though its deferred tools work when called.
    Unavailable GPT pins in the picker show a context figure absent from
    live rows.
19. **Two findings from the last drives run.** Grep passes ripgrep the real
    path of its search root so anchored globs match under symlinked
    folders on macOS. The boot-time account read uses the same base
    address as the usage read.
20. **Check every hard-coded model id against live catalogues at release.**
    One source file contains fourteen manually entered GPT ids. For nine
    days, every GPT session's side jobs were assigned a retired id
    (gpt-5.4-mini) before the issue was found. The check rejects ids missing from the live list.
21. **Three Windows findings from this release.** Interrupting a shell
    tool misses grandchildren reparented after the shell exits, leaving
    a loop running. The fix needs a kill-on-close job object around each
    spawned shell. A native module that starts the shell inside the job
    was drafted and reviewed but remains unfinished. Completed commands
    must keep their background processes, as on macOS. Short multi-line
    bracketed pastes under ConPTY do not create paste chips because the
    terminal strips the markers before Mercury receives the lines. The
    five-process stale-ending scenario with a genuinely disconnected
    session, and the unkillable case, still need testing on Windows.
22. Carried from the earlier plan: the dependency index; coverage and
    test-to-debug; a scan mode with a read manifest; GNU bash 5 vendored;
    the small words.
23. For 1.0.0-beta.18: preserve a live runner across daemon restarts so an
    installed update reaches the daemon and its chats once the open chats
    close. Also add the crew-agent view, allowing a switch from the chat
    to a crew mate's or sub-agent's own view.
24. **shift+B backgrounds a running shell command.** Escape interrupts
    both the waiting agent and its shell command, losing the command's
    work. Keep that behaviour. While a shell command runs, shift+B sends
    it to the runner as a background task and frees the agent, with a
    notice explaining where the command went. Show the key in the hint
    row and ready line only while a shell command is running.
25. **Extend quiet retries to other providers.** 1.0.0-beta.16 quietly
    retries Gemini busy errors for about a minute. OpenAI, Z.AI and other
    compatible providers still retry once immediately, then show a red
    error. Move them to the same retry schedule. Rate limits without a
    provider-specified wait still get one retry. On a session's first
    turn, the chat currently shows no retry notice while retries run.
    The original item: **Gemini "high demand" errors get one immediate
    retry, then a red line.** Google's HTTP 503 says the model is
    experiencing high demand and to try again later. Mercury retries after
    0.4 s, then displays an API error. Retyping a minute later works. Use
    several retries with increasing waits, as documented for the other
    providers. Keep them quiet for the first thirty to sixty seconds,
    since these errors usually clear within seconds. Show a retry line
    after that and a red error only when the wait is exhausted.
26. **For 1.0.0-beta.20: harness sync, a first step toward a
    meta-harness.** An opt-in `/harness-sync` command runs once per project.
    An agent you choose in a Mercury session imports the project's notes,
    rules, memory and settings from other harnesses. It uses a simple
    prompt with some enforcement and a warning that Mercury can make
    mistakes and that the task needs a reliable agent. A dedicated screen
    with custom prompting is also possible. Auto-sync is separately
    opt-in. When Mercury opens a project worked on in the last thirty
    days by one of the twenty to twenty-five most-used harnesses, it
    syncs. The harness locations are already listed; the selection will
    be settled then. Projects Mercury has never opened sync regardless
    of age. The thirty-day window applies after that, checking for new
    work from that harness and avoiding conflicts through mechanical
    checks where possible to save time. Later, auto-sync could be a
    config setting within permissible bounds, making it easier to switch
    harnesses. It remains opt-in.
27. **Rewrite and centre the first-run cards.** The welcome and setup
    frames, theme picker, sign-in, trust and permission cards will use
    concise, direct wording without forced personality or machine-written
    phrasing. The owner chooses the model for this edit. Centre the cards
    on screen instead of the top left, and replace amber with light brown.
28. **The chat shows "thinking" while waiting for an agent.** After a
    sub-agent starts, the runner reports once that it is waiting for the
    agent. The chat can receive that status a few milliseconds before
    it learns the runner is busy, discard it, then show "thinking" for
    the entire wait. This is rare with a real model but reproducible with
    a fast one. Keep the waiting status until the runner reports idle,
    or repeat it while agents are running.
29. **Clicking outside a panel closes it.** Chat panels that close with
    Escape, including the agent card and other overlays, should also
    close when you click the dimmed chat behind them. That click closes
    only the panel; it does not select or activate anything underneath.
    The Boot face's layers remain Escape-only for now.
30. **Two findings from the last drives run.** On Linux, the process sweep
    classifies every Mercury process as not ours. The process table's
    executable column contains the main thread's name, MainThread,
    instead of node. The doctor counts these as not ours, so the sweep
    ends nothing. macOS reads the executable's name and is unaffected.
    Separately, loading a transcript while its last line is still being
    written marks that line as malformed and briefly shows "transcript
    degraded on load". The next read completes it. This was seen once on
    the hosted runner.
