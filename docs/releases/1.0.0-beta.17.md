# 1.0.0-beta.17 — queued

**State:** queued behind 1.0.0-beta.16. The road ahead, as decided while
1.0.0-beta.16 shipped: 1.0.0-beta.17 is short — the full-screen critter's
opt-out and the crew-agent view (items 12 and 13); 1.0.0-beta.18 hardens
Mercury by running it on every provider it supports, on a machine that can
take the load, and fixing what that finds at the root — each model works on
its own sign-in and account handling inside a sandbox made for it, everything
it does is treated with suspicion and verified, so the multi-account road is
tested on real complex work, that work being Mercury itself; 1.0.0-beta.19 takes
the live runner across the daemon's restart (item 22); 1.0.0-beta.20 image
generation as a tool, or the rest of this page first; 1.0.0-beta.30 is the
release candidate that leaves beta. Provider breadth (Grok, Muse) rides
where it fits; Perplexity waits for after the beta. The rest of this page is
what the 1.0.0-beta.16 line still shows.

1. **Grok and Muse as providers**, with a live model list where the provider
   serves one and a dated table where it does not; Perplexity after the beta.
2. **The model picker refreshes every family's list in the background** when
   it opens on a cached list — the OpenAI rows do this from 1.0.0-beta.16;
   the OpenRouter, Gemini, Hugging Face and local rows follow the same
   changed-only rule.
3. **`/cost` typed during a turn** paints at once, like `/status` and
   `/usage`, reading the focused session's own cost figure instead of the
   process's cost tracker.
4. **The crew board's stopped rows:** pressing r on a stopped named teammate's
   row respawns the mate (today the resume refuses it while the row still
   offers it); the main agent is told when the operator stops or resumes an
   agent from the board; a teammate row registered against a team that does
   not exist is unwound at the spawn's refusal instead of standing as running.
5. **The sign-in names its account everywhere:** the transcript's
   "Login successful" line names the account, and the in-app sign-in reads
   the account's organisation so `/status` keeps the organisation name after
   a switch.
6. **A new chat's effort chip paints its word plain** from the first frame,
   instead of "(asked)" for the second before the session confirms it.
7. **The compact board's contract offer card** overflows its pane at 80×14
   and 82×17, clipped above its question and its Yes/No rows.
8. **A daemon that leaves in the beat after answering a new window** still
   costs that window one retry ("daemon closed without a reply"); the birth
   could re-run its daemon check once.
9. **Two small screens after a failover:** at 80 columns the failover
   sentence is cut at the width, its "/model to return" tail off screen; and
   the compact composer at 80×21 says the session is landing under a band
   that already says ready.
10. **The cockpit's usage windows and pools reaching the runner** (the reverse
    of 1.0.0-beta.16's relay), so a runner's own notice reads the endpoint's
    record too.
11. **Gemini after a real Google sign-in:** when Google refuses because the
    Gemini API is not enabled on the account's project, the picker's row
    carries Google's own instruction instead of "re-connect"; the Gemini rows
    whose ids sit outside the routable `gemini-` space (the music, agent and
    deep-research previews) are routed if they speak the chat call or hidden,
    and two rows sharing one display name are told apart; a live model switch
    on the Boot Menu's model row, which today only points at the chat's
    `/model`.
12. **The composer at a chat's landing, the New Session strip's effort
    indicator and the count rows on small screens**, after designs; a new
    session starts on the last-selected effort and model.
13. **A file explorer beside the chat**, the way VS Code shows one (an
    explorer, not a tree viewer), after a design; a switch between the chat and a crew mate's or sub-agent's own
    view; a command that shrinks the full-screen critter to a small one and
    gives the chat its rows back.
14. **The workspace trust card can flash for a split second at boot** on a
    trusted folder; seen once, not yet reproduced.
15. **A message from one Mercury session to another** lands as a notification
    the way messages between agents in one session now do; and a message to
    a crew mate from the chat, which today refuses for want of a team.
16. **Mercury processes left behind:** a daemon started by a headless run with
    no window outlives it, and a window's process can stay after its parent
    is gone; the daemon's boot or the doctor could find and end them. A window
    whose terminal died can hang in the kernel on macOS: two such windows sat
    three days in an uninterruptible wait, and an open of that terminal's
    device took the reading process the same way — so where Mercury opens its
    terminal device, and whether a window can meet that wait, is a read owed.
17. **The daemon's supervisor record written atomically as a whole** (its
    boot write, the owner hand-over and the stopping mark) through the
    substrate's publish door, instead of the plain writes it takes today.
18. **Three small reads from the sanity walk:** the daemon log's first line
    carries its timestamp at the tail; a background sub-agent's tool search
    says it is not enabled while its deferred tools work when called; the
    picker's unavailable GPT pins show a context figure the live rows do not.
19. **Two reads from the last drives run:** the Grep tool hands ripgrep the
    real path of its search root, so an anchored glob under a symlinked
    folder matches on macOS; the boot-time account read follows the same base
    address the usage read does.
20. **Every hand-typed model id checked against the live catalogues** at
    each release: one source file carries fourteen GPT ids typed by hand, and
    a retired one (gpt-5.4-mini) fed the side jobs of every GPT session for
    nine days before it was read; the check refuses an id the live list does
    not serve.
21. **Three Windows items from the Windows reads of this release:** an
    interrupted shell tool's tree-kill misses grandchildren reparented after
    the shell exits, leaving a loop running (a kill-on-close job object
    around every spawned shell is the remedy; a native module that starts
    the shell inside the job was drafted and reviewed but not finished, and
    a completed command must keep its background processes as on macOS);
    a short multi-line bracketed paste under ConPTY does not mint a paste
    chip, because the terminal strips the paste markers before Mercury
    sees the lines;
    and the five-process stale-ending scenario on a genuinely disconnected
    session, and the unkillable shape, remain to be driven on a Windows box.
22. Carried from the earlier plan: the dependency index; coverage and
    test-to-debug; a scan mode with a read manifest; GNU bash 5 vendored; the
    small words.
23. For 1.0.0-beta.18: a live runner handed across the daemon's restart, so
    an installed update reaches the daemon and its chats once the open chats
    close.
24. **Escape ends a working shell command.** Pressing Escape to interrupt an
    agent that is waiting on a shell command ends that command too, and the
    work it was doing is lost when it could have gone on in the background.
    Either Escape ends only the agent's own waiting (a sleep, a poll) and
    leaves a command that is doing something running, or Escape keeps its
    meaning and a second key (shift+B) hands the running command to the
    runner as a background task. Small or large depending on the road
    chosen.
25. **The quiet retry for the other providers.** 1.0.0-beta.16 retries a
    Gemini busy refusal quietly for about a minute; OpenAI, Z.AI and the
    other compatible providers still get one instant retry and then the red
    line, each one setting away from the same ladder. Also: a rate limit
    without a wait from the provider stays on the single retry; and on a
    session's first turn the chat paints no retry notice while it runs.
    The original item: **A Gemini "high demand" refusal gets one instant retry, then a red
    line.** Google's HTTP 503 (its own words: the model is experiencing high
    demand, try again later) is retried once after 0.4 s and then painted as
    an API error; the person retypes, and it works a minute later. A refusal
    that says try again later deserves a few retries with a growing wait
    before the red line, as the other providers' roads are read to do — and
    quietly: nothing is painted while the retries run for the first thirty
    to sixty seconds, since the refusal usually clears in seconds; the retry
    line appears only past that, and the red line only when the wait is
    spent.
26. **For 1.0.0-beta.20: the harness sync, a first step toward a
    meta-harness.** An opt-in command, `/harness-sync`, runs once on a
    project: the agent of your choice in a Mercury session adopts what the
    other harnesses saved about that project (their notes, rules, memory
    and settings) with a simple prompt, some enforcement, and an honest
    line that Mercury can make mistakes and that a reliable agent should do
    it; possibly a small screen of its own with custom prompting. Auto-sync,
    also opt-in: whenever Mercury opens a project that one of the twenty to
    twenty-five most used harnesses (the homes already listed, settled then)
    worked on in the last thirty days, it syncs; a project Mercury has never
    touched syncs whatever the age of that work, and the thirty-day window
    applies from then on to notice new work from that harness and avoid
    conflicts, mechanically where it can be so no time is wasted. Later, an
    auto-sync in the config within permissible bounds, so people can switch
    over seamlessly, only ever on opt-in.
27. **The first-run cards, re-authored and centred.** The cards a person
    meets on a first install (the welcome and setup frames, the theme pick,
    the sign-in, the trust and permission cards) are rewritten in the house
    voice — concise, clear, straight to the point, no quirk and nothing
    that sounds machine-written — by the model the owner names for it;
    they sit centred on the screen instead of the top left; and their
    yellow gives way to a light brownish colour.
28. **The chat says "thinking" over an agent wait.** After a sub-agent
    starts, the runner says it is waiting on the agent once; the chat can
    read that word a few milliseconds before it learns the runner is busy,
    throws it away, and paints "thinking" for the whole wait. Rare with a
    real model, reliable with a fast one. The fix keeps the waiting word
    until the runner reads idle, or repeats it while agents run.
29. **Clicking outside a panel closes it.** In the chat, a panel that
    Escape closes (the agent card and the other overlays over the chat)
    also closes when you click the dimmed chat behind it. The click only
    closes the panel; nothing under it is selected or acted on. The Boot
    face's layers keep Escape only for now.
