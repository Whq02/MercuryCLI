# 1.0.0-beta.27 — ready for the tag

**State:** ready for the tag. This release makes Mneme Mercury's
memory, on by default; mercury run the headless command with text, JSON and
row output; mercury daemon and mercury health the background helper's and the
health check's one command each; and a project's AGENTS.md its guide. It adds
mercury runner for host programs, the tokens each sub-agent has used in the
crew view and a JSON export of the chat, and fixes a resumed session losing
its model, an update leaving open windows behind, doubled sub-agent records,
secrets printed in full, and the usage rows and retries on the
OpenAI-compatible models.

## What changed

- Added mercury runner, a session served to a host program over stdio
- Added the mercury-docs skill, which answers how to use Mercury from its own
  docs, and /verify, an adversarial check of the session's work
- Added review runs, an Agent launch that reads one commit and writes one
  report
- Added a terminal ping when a chat finishes while you are away; off with
  view.ping
- Added hooks that run in the background and wake the model when they finish
- Added the tokens each sub-agent has used, beside its context in the crew
  view
- Added /export to a .json name, a JSON copy of the chat
- Added an OpenRouter routing policy in /config, on from the start
- Added a low-balance notice in /usage for an OpenRouter key
- Added vulcan status saying when the Godot addon is out of date
- Mneme is Mercury's memory, on by default: what Mercury learns about a
  project is kept in plain topic pages, your pinned rules stay in front of the
  model word for word, and matching facts are recalled as you work; /memory
  shows the facts, the rules and how full the pinned shelf is, and /config
  sets the shelf's size
- mercury run is the headless command, with --format text, json or rows: one
  JSON row per line for the session, each turn's text, reasoning, tool calls
  and results, and one outcome row with the status, the answer, the usage and
  the cost
- mercury daemon run | status | stop | restart is the background helper's
  command; status lists every helper of the home with the chats each still
  hosts
- mercury health and /health are the health check, with a Health Check row on
  the start screen
- Settings are grouped in settings.json and /config: engine, guardrails,
  memory, records, credentials, view and the rest, as the settings page lists
  them
- A permission rule covering a command and whatever follows it is written
  Bash(npm run *), and Skill(deploy*) covers every skill a name begins; the
  consent cards' "don't ask again" writes that form
- A project's AGENTS.md is its guide when it has no MERCURY.md; a personal
  MERCURY.local.md loads beside it
- The built-in agents are mercury-crew, for delegated work of every kind, and
  the read-only mercury-scout
- Fixed resuming a session losing the model it was started with when none of
  its turns had been answered
- Fixed a Mercury window left open through an update losing its sends: the
  window keeps working on the build it started with, new sessions run on the
  updated one, and mercury update says so on its last line
- Fixed mercury update on a Homebrew or npm install saying nothing about the
  background helper or open windows; --json carries both
- Fixed an update leaving the background helper on the old build without a
  word: a helper of another build is named on screen and in /health, and a
  restart moves it once its chats finish
- Fixed a background helper that had handed over to a newer one staying up
  after its own last chat ended, and an idle helper of the previous release
  staying up after an update until stopped by hand
- Fixed two Mercury windows starting the background helper at the same moment
  leaving an older helper's chats unreachable
- Fixed mercury daemon restart refusing while an older helper still hosts
  chats: it waits for them and says which helper and how many chats it waits
  for
- Fixed mercury daemon stop run from inside a chat hosted by an older helper
  ending that chat; its count now covers every helper's chats
- Fixed mercury daemon run --help starting a helper instead of showing the
  page
- Fixed the --help pages using Mercury's own names before saying what they
  mean: every page gives the plain words first and names the thing once, and
  the permission modes, the budget's unit, the tool-rule shape and the
  settings sources are explained where they appear
- Fixed an answer that ends before it starts failing the turn: Mercury tries
  again, three times with a short wait, and the spinner counts the attempts
- Fixed a session opened in the few milliseconds while a newer background
  helper was taking over answering "unknown"
- Fixed a session that ran a short slash command or /clear through the
  background helper staying marked busy for good
- Fixed a saved default permission mode being read differently depending on
  how the session was started: a session born from the Boot face or the
  Concourse opens the posture a direct launch would, and an agent's permission
  mode never exceeds the session's own consent
- Fixed Shift+Tab stepping through Strategy mode; Apollo Mode now takes that
  stop and the ◇ mark
- Fixed editor interviews so answers reach Mercury, including in Apollo Mode,
  and cancelling an editor prompt before it starts so the first cancel settles
  it
- Fixed editor sessions waiting indefinitely after a host and runner disagree
  on their protocol
- Fixed a session reopened from an editor over ACP coming back in the default
  permission mode instead of the one it was left in
- Fixed sessions staying busy after a host's connection is refused, or waiting
  indefinitely for a host that never answers, and a refused prompt being
  reported as accepted
- Fixed a failed turn reporting the wrong turn number, a shell turn losing its
  output or reporting completion after an interruption, and tool progress
  attributed to the wrong call
- Fixed duplicate start and finish updates during compaction, and missing
  completion updates when automatic compaction fails or is cancelled
- Fixed a resumed session seeing only one result of a parallel tool batch
- Fixed an image whose size cannot be read being sent anyway in a request over
  the many-image limit: it is left out with a one-line note and the transcript
  keeps it
- Fixed a hook whose matcher is * never running
- Fixed a misspelt settings key doing nothing in silence: the health check,
  the chat's settings notice and the start of a headless run name it, and
  /config shows only settings Mercury reads
- Fixed an invalid guardrails.mode being accepted; it is answered with the
  modes Mercury has
- Fixed mercury run --help promising a title or a picker for --resume: run
  takes a session id or a transcript path, and its help says so
- Fixed --log-file leaving a latest link beside the file it was given
- Fixed mercury update on a source checkout downloading a release: the check
  and the status name the rebuild, and the update refuses first
- Fixed the first run preselecting "yes, set it up" on the Terminal keys step;
  the step is opt-in, and a provider key already in the environment skips the
  sign-in step
- Fixed the trust-this-folder screen and the first-run guardrails to say
  plainly what trusting a folder means
- Fixed a WebFetch(domain:*.example.com) rule not covering every host under
  the domain
- Fixed a rule's decision being worded differently in each place it appears:
  rm -rf dist is denied by the rule Bash(rm *) in the shared project settings.
  is the one voice, with your own reason on the end
- Fixed a grep flag reaching the Grep tool being refused without the Mercury
  parameter that does the same thing
- Fixed mercury-scout writing through tools other than the shell; the scout is
  offered only the tools that read, and a review run is offered only the tools
  it can use
- Fixed a failed language-server call saying nothing useful: it tells you what
  happened and what helps, and the same failing call is answered three times,
  then refused for the session
- Fixed the LSP tool refusing arguments it advertises; a documented key an
  operation does not use is ignored
- Fixed memory: a rule you ask Mercury to remember is on the pinned shelf at
  once and the next chat follows it; a fact or rule is kept even when a model
  fills every optional field; /memory lists the topics and each opens its page
- Fixed memory search answering only an exact phrase; Recall answers the words
  of a question, and a short fact made of those words comes first
- Fixed a command run from a Mercury session inheriting the session's own
  config home and launcher variables; it sees your environment
- Fixed health processes counting another Mercury build's processes as this
  one's, and a fresh home's health check calling Mercury's own helper record a
  foreign tool's
- Fixed the Boot face's health chip not showing the certificate from your last
  /health run
- Fixed a workflow run disappearing from Inspect, the telemetry rail and the
  /workflows board after the session's shell changed folder
- Fixed each worker's file leases: a worker keeps its own, and a project's
  handoff files can be leased beside source files
- Fixed a stopped workflow losing its workers' tool-use counts, and its
  receipts not naming the run state apart from the transcripts
- Fixed Read clipping an oversized row silently; the clipped part is marked
- Fixed the crew tools answering a session with no crew with an error saying
  its crew does not exist; they now say plainly that the session is not in a
  crew
- Fixed a local crewmate's context staying blank after a reply
- Fixed every sub-agent turn being recorded twice in its transcript
- Fixed a sub-agent's answer to a message from the crew view also landing in
  the lead's inbox
- Fixed mcp get, mcp list, mcp add and the /mcp screen printing a server's
  secret values in full
- Fixed an exported chat carrying API keys and tokens in full; they are masked
  in both the text and the JSON
- Fixed a run's rows showing zero usage on Grok, DeepSeek, Kimi, GLM and the
  other OpenAI-compatible models
- Fixed a resumed mercury run reporting API time and cost from earlier runs
- Fixed the reasoning-token count missing from Grok and other
  OpenAI-compatible results
- Fixed the Patience setting being ignored on Grok, Kimi, DeepSeek, Gemini,
  Muse, OpenRouter and Hugging Face
- Fixed a temporary capacity or network error from OpenAI, Grok or OpenRouter
  ending the turn instead of retrying, and a network error ending a Kimi,
  DeepSeek or other compatible-provider turn
- Fixed overloaded sessions sending their retries in lockstep
- Fixed a slow model's turn being cut off after two minutes of silence; the
  normal wait is six minutes now, twelve in patient mode
- Fixed a settings popup hiding the session header while it was open
- Fixed the Kimi 5-hour usage window reading 0% in /usage while requests were
  being spent
