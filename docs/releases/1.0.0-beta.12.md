# 1.0.0-beta.12 — queued

**State:** queued behind 1.0.0-beta.11 (the maintenance tag of 2026-09-13). The
defects met in the owner's own sessions on 2026-09-13, each one a user meets,
plus one item carried from the earlier list; everything else that was queued
here moved to [1.0.0-beta.13.md](1.0.0-beta.13.md) by decision that day. The
verdict, the tag commit and the publish line are written at the tag.

1. **The Git tool finds the repository.** The tool runs only in the folder the
   session opened in and never looks for a repository above or below it: a
   session opened on a parent folder is refused with "not a git repository"
   while a plain shell command with a folder argument works. The tool takes
   a path, walks up from it, and finds the one repository directly below the
   session folder; the refusal names the folder it looked in.
2. **Images on the OpenAI route.** The pre-send image limit for OpenAI is a
   wrong number, so Mercury's words name a limit the provider does not
   enforce; and after a refused image a resume sends the same image history
   again, because the recovery that strips a refused image from later
   requests exists only on the Anthropic route. The real limit at its one
   home; the strip wired for the OpenAI route; a proof per route.
3. **A restarted runner says why.** The notice "… was stopped — the session's
   runner restarted before it finished" carries no reason, though the daemon
   knows it (a crash, a reconfigure, a park). The reason travels to the
   runner and into the notice.
4. **The context overflow on a model switch.** Switching a large conversation
   from a Claude model to a GPT model overflowed the provider's window with
   no check before the first request; the recovery folded on the same
   too-small model and retried by dropping turns; the notice carried no
   numbers. A check before the switch that folds or warns, the summariser on
   a model that fits, the notice with Mercury's own count, and the stale
   window note in the catalogue code retired.
5. **The queued line, hardened.** The 1.0.0-beta.11 fix proved against the
   arms the sanity lane did not reach: a fork, a nested sub-agent, a workflow
   agent, a line at the moment the Agent tool returns, a line during a
   sub-agent's fold, a relaunch mid-sub-agent, two queued lines; a second
   guard at the queue owner itself; a sweep of the session records for any
   doubled row that is not a stray echo beside a re-send; a crew notice
   during a sub-agent's run.
6. **The doctor.** `mercury doctor --json` writes the global config and a
   large verify index on every run, and a health check must be read-only;
   the daemon sign-in row fails on a catalogue timing gap between two
   processes and tells the operator to restart the daemon, which would not
   help.
7. **A boot from a deleted folder** crashes with Node's own sentence and
   leaves a crash notice for the next boot; one plain line and an exit
   instead.
8. **The daemon's throwaway warm runner.** Every daemon boot pre-spawns a
   runner it retires at once for consent drift, then spawns another, during
   the boot's memory peak.
9. **A closed terminal leaves a screen behind.** A Mercury screen whose
   terminal closed while the release-channel check was in flight sits for
   days behind a `gh api` child that never returns (nine found on the
   owner's Mac); the orphan road must end the process without another write
   to the dead terminal, and the gh call's timeout verified live.
10. **Godot, carried from the earlier list.** The scene tree read over the
    debugger protocol, live queries during a capture or profile boot, and a
    doctor row naming a retired setting still set (`MERCURY_GODOT_TOOLS_PORT`,
    `_TOKEN`).

11. **Stopping a task that already finished.** A background shell run
    completes, its record leaves the task registry after a grace, and a
    later stop of that id answers the bare "No task found with id …" as an
    error, so agents are seen stopping tasks that do not exist. The stop
    answer for a finished shell task names the fact — completed, when, and
    where its output file is (`src/utils/task/diskOutput.ts` knows the path)
    — the way it already does for a finished agent whose transcript is on
    disk (`src/tasks/stopTask.ts:41`), and a stop of a finished task is not
    an error. Seen 2026-09-13 21:20 BST in the owner's session: a run that
    completed at 21:07 was stopped at 21:20 and refused with the bare miss.

12. **Teams that survive.** Moved here from the 1.0.0-beta.13 page by decision
    on 2026-09-14. A teammate that dies at spawn is reported as running: the
    Agent tool answers "spawned … running", the teammate's own notice says
    failed a second later, and the lead sends work to a dead seat. A restarted
    lead loses its team: the team folder keeps only its leases, the resumed
    session says it is not part of a team, and the team tools then disagree
    about it. A workflow whose agent fails answers "completed with failures"
    with no cause; the failure line carries the first agent's cause. Seen
    2026-09-10 while Mercury worked on itself.

**Not a product item**, one command on the owner's word: the nightly workspace
backup has failed since 2026-09-03 because its script is not deployed beside
the launcher (`scripts/ops/deploy-backup-agent.sh`).

**Hygiene, not user-facing, the owner may strike:** a sweep of dated numbers
and "observed" notes in code comments (one misled a diagnosis on 2026-09-13),
with a check that refuses new ones.
