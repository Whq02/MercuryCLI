# 1.0.0-beta.16 — ready for the tag

**State:** ready for the tag. A short update on quality: the defects met on the
day 1.0.0-beta.15 shipped, a session's own usage cap reaching the failover
offer, the compact chat right from its first frame, the crew board's stop
made true, and the fixes from Mercury working on itself.

**Verdict:** hosted gate run 35547111848 on the release line's published tree
(commit 412733cf5), 138 of 138 release suites green; the gate-ledger row whose
code tree equals the tag's. The terminal drives, an advisory class, read 71
of 77 suites green on run 35535423099. Every red was read at its cause:
three proofs assumed a Mac-only path, one suite ran past the runner's
default ceiling with its members green, one proof pinned a request order
that had changed, two proofs raced the slower runner, and two were product
faults, one fixed here (a sub-agent's transcript dropped its recovery rows)
and one queued for 1.0.0-beta.17 (the chat paints thinking over an agent
wait). A further run on the fixed line reads those proofs again.

## What changed

- The Anthropic sign-in's receipt names the account that just signed in: the
  account comes from the sign-in's own result and is stored the moment the
  credential is saved, so the Logins card, the boot screen's chip, `/status`
  and the stored account follow at once instead of staying stale until
  `/accounts`.
- The Edit tool lands a file of no known language byte for byte: only prose
  (Markdown, plain text, AsciiDoc) keeps typographic quotes; a file with no
  extension, a dotfile or a suffix outside the highlighter's registry keeps
  the bytes the model sent.
- An Edit of lines not yet read, in a file the session has read as it stands,
  lands in one call; its result carries the edited lines with fresh anchors.
  A file never read still asks for one read first, and every refusal says
  first what to do.
- A pasted text chip carries the hash of its bytes, stored at the paste: a
  send resolves the chip from the store and says so by name when the bytes
  are gone; a draft over its budget keeps the chip as a reference; the paste
  sweep keeps what a draft or the history still names.
- A session turn's usage cap reaches the failover offer card: the runner's
  window verdict rides the session facts to the cockpit, which merges it into
  the one latch the card reads, so a capped reply on a session's own turn
  raises the card and marks that provider's row.
- The context figure on the rail drops its published-window mark as soon as
  the session's runner has fetched the live model list, without opening the
  picker.
- The compact chat's mode chip, and the full cockpit's mode band, paint from
  the first frame of a new chat: a chat born from the boot screen or the board
  carries the model, effort and mode it was born with until its session's own
  facts take over.
- A new chat on a Gemini model whose Google account or stored key was present
  but refused by the model catalogue no longer says "no credential": the
  refusal names the source it tried and the status it got, and says how to
  recover.
- Pressing x twice on a running sub-agent's row in the crew board stops a
  named teammate as well as a dispatched sub-agent; the receipt says applied
  only once the row has ended and refuses with the reason otherwise; TaskStop
  accepts a teammate's name or its full id.
- The shell result's note about scrubbed session variables appears once per
  session, once more after a context compaction, and otherwise only as a
  short line when a command names one of them.
- The THEMIS blocklist no longer refuses a read-only `git config` query for
  the hooks path, and matches a command's words rather than text a heredoc or
  a quoted string writes to a file.
- Every line the daemon writes to its log carries an ISO timestamp.
- The cache-clock record lands beside the session's transcript, not under a
  mirrored copy of the config home's path inside the projects folder.
- WebFetch summarises with the session's own model when its summariser model
  is not signed in, and if that fails too returns the page with a note naming
  what it tried.
- `/status` no longer closes the view and exits Mercury when `CI` is set in
  the environment with no API key variable: the status card reads the
  credential refusal as "no key" and paints the stored account as it does
  without `CI`.
- A background command's completion reaches the agent at the next tool
  boundary of a running turn, with its notification frame on the wire, and
  anything still undelivered is read at the turn's end; nothing waits for the
  operator's next message.
- A new chat whose saved default model's family has no usable credential no
  longer refuses to start: it starts on the newest signed-in family with one
  warning receipt naming the saved family, the reason, the family it runs on
  and the way back; `/model` inside that chat saves a new default and the next
  New Session runs it.
- The Gemini picker's refusal names the source it tried and the HTTP status
  it got, with the remedy on its own segment, and the debug log keeps one
  masked line per refused catalogue read.
- A stored Gemini key of the test fixture's shape is named as a test key on
  the Logins card and `/accounts`, with the key to remove it, and Mercury's
  own checks can no longer write one into a real store.
- A Mercury window opened while the previous daemon is still shutting down no
  longer waits up to thirty seconds and refuses: the daemon marks its record
  as stopping the moment its shutdown begins, and the new window starts its
  own the moment the old one has left, never two on one config home.
- When a background completion and a message you typed both wait at the end
  of a turn, your message starts the next turn and the completion is read
  inside it, instead of the completion taking a short turn of its own first.
- A confirmed failover keeps its note: the session facts published when the
  model switch lands name the switched model, so the cockpit no longer reads
  a stale publication as a return home and clears the failover sentence and
  the strip's mark.
- The model picker opens at once on the GPT rows it has and refreshes the
  live list in the background, replacing changed rows in place with a
  one-line notice instead of showing a minutes-old list unchecked; the
  highlighted row follows its model when rows move.
- Messages between agents arrive the way a finished background command does:
  a background sub-agent can message its main agent, and a message from the
  main agent reaches a sub-agent, each read at the receiver's next tool
  boundary or at the end of its turn, starting a turn when the receiver is
  idle, with a notification frame on the wire and a receipt saying when it
  is read.
- Gemini through a Google account works in the chat again: Google's
  OpenAI-compatibility endpoint refuses the Google account's token that its
  native endpoint accepts, so a chat born on the Google-account source now
  speaks Google's native generation call, streamed, with tool calls, usage,
  the context ceiling and Google's thought signatures preserved across tool
  rounds and resumes; a Gemini API key keeps the compatibility endpoint. A
  refusal from Google carries Google's own reason (the shared error reader
  expected an object where Google sends an array, which is why only
  "HTTP 401" showed), and the quota remedy for a Google sign-in names what
  can be done.
- **Signing in to Gemini is guided.** The Gemini card offers the API key
  first: it opens the AI Studio key page and takes one paste. A Google
  account is six numbered steps, each opening its Google Cloud Console page
  (the project, the Gemini API switched on for it, the consent screen's
  audience with your own address as a test user, a desktop OAuth client, the
  client id pasted and kept, the browser sign-in past the unverified-app
  screen); a refused sign-in returns to the step that answers it, and a
  stored client id starts at the last step. The Boot face's Logins row
  speaks the same words. The Console addresses are dated facts, and the
  release-day check fetches each one and refuses a dead page.
- **A busy Gemini is retried quietly.** When Google answers that the model
  is busy, Mercury sends the request again after 1, 2, 4, 8, 16 and 30
  seconds, about a minute in all. Nothing is painted for the first thirty
  seconds; after that the retry line shows the true wait and attempt, and
  the red error comes once when the minute is spent, naming the count and
  the time before Google's own words. A recovery paints one calm line above
  the answer. Escape ends a wait at once. Other providers keep today's
  single retry, and the retry line reads "Retrying now…" when its countdown
  reaches zero on every road.
- Every side job of a GPT session asks a model the account's live list
  serves. The chat's title, the away summary, the tool summaries, the state
  read, the feedback card, the date parser and the web fetch summary had
  asked for a helper model from a typed table that OpenAI had retired, so
  Mercury's own check refused it before any call; the helper tier and the
  hook agent's tier now come from the live list (the cheapest served text
  model, and the newest served plain model below the frontier), never from
  an id the list lacks, and the session's own model serves when the list
  serves none. The web fetch tool counts a summariser's refusal as a failed
  leg and asks the session's model instead of returning the refusal as the
  summary. A release-day check compares every typed model id with the live
  lists the signed-in credentials can fetch, and the coordinator picker
  shows a remembered or configured model the live list no longer serves as
  not in the catalogue.
- Mercury processes the doctor can end. The doctor's new "Mercury processes"
  row counts what is running, stale, cannot be ended and not Mercury's, lists
  each stale one with its pid, terminal, age and reason, and offers "Review
  stale processes", which ends them only after showing the list and asking;
  a process in a kernel wait is reported as "cannot end — needs a reboot",
  never claimed. Nothing is ended at boot: the boot reads and records.
  Staleness is read from Mercury's own facts (a live terminal, a live
  session, a live window behind a daemon) and never from a parent pid alone,
  so another running Mercury is never ended, and a probe never opens a
  terminal device. The same runs headless as mercury doctor processes, with
  --end-stale after the review.
- A Moonshot sign-in's default model and picker rows come from the
  provider's live model list. They came from a typed table, and no live list
  was ever fetched, so a model Moonshot had retired became a refused chat
  with nothing saying why (the same class that fed every GPT session's side
  jobs a retired id). A live catalogue reader on Moonshot's documented models
  endpoint now feeds the default row, the picker rows and the dispatch
  adapter; a named model the fetched list lacks is refused before the call
  with the catalogue's own words, shared with the GPT road; the typed table
  serves only until a list has been fetched, with its date in its words.
  Three retired GPT ids left the typed table. Z.AI documents no models
  endpoint and keeps its dated table, its unknown-model refusal carrying the
  provider's own reason. A census refuses any typed table used as a chooser
  without a live check.
- **The doctor judges every typed model id against the live lists.** A Model
  lists row reads, for each family, the live list this process fetched and
  the typed ids Mercury carries: a typed id the list lacks is a warning that
  names it, a family whose list was not read in this process says so and how
  one is read, and Moonshot is judged against the account's cached list like
  the others. Z.AI publishes no model list, so its typed ids read the dated
  table, and the release-day check probes them by one minimal completion
  each only behind `--probe-by-completion`, which sends nothing when the
  switch that stops all catalogue traffic is set. The DeepSeek and Moonshot
  list readers name a body that is not JSON and an endpoint that could not be
  reached in one sentence each, with the cause's code.
- The process sweep reads Windows too: every process through the system's
  own management interface with its real executable, arguments, birth and
  session, and for Mercury's own rows the owning account and the terminal
  facts; an unknown read is never permission to end anything; an ending
  re-checks the process's identity and terminal immediately before acting
  and ends that one process only, forcibly only when Windows allows no
  polite stop. Proved on a real Windows machine: a daemon with a live owner
  read as running, and of six staged processes exactly the three stale ones
  were ended. The test census follows every driver on Windows. The Windows
  walk of this release also fixed the capture config's encoding and its wait for the composer row, a
  bare git config read of the hooks path staying clear of the write block
  when another command follows, the Gemini catalogue's unreachable state
  naming the source and the remedy, and the rail's context row read after
  the picker closes.
- A stream cut the model continued from paints one calm line. When a
  provider closes the connection mid-answer, Mercury's one bounded
  continuation recovers the turn; the chat now shows a single quiet line in
  the collapsed tool row's style, "Continued after 1 stream cut · context
  sent again", instead of the red error card, the warning and a note about
  replayed turns, with the road, what the provider sent and the code one
  expansion away; the red card stays only when the recovery is exhausted or
  refused. Every cut writes its forensics to the debug log so the cause can
  be read from the record.
- Two lines typed in a row behind a finished background command share one
  turn, and the command's notice is read inside it, instead of a short extra
  turn for the notice sitting between the two lines; a shell line still ends
  the batch as it always did.
