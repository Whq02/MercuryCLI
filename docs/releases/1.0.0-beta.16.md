# 1.0.0-beta.16 — published 2026-09-21

**State:** published 2026-09-21 as a pre-release at
github.com/Whq02/MercuryCLI/releases/tag/v1.0.0-beta.16, tag on commit 06dd22c2.
This update fixes issues found when 1.0.0-beta.15 shipped and while using
Mercury to develop Mercury. It also fixes usage-cap failover, the compact
chat's initial display and stopping agents from the crew board.

**Verdict:** hosted gate run 35548508730 passed 138 of 138 release suites on
the release commit's published tree (commit f6718fb5). That gate-ledger
entry has the same code tree as the tag. Earlier run 35547111848 passed the
same 138 suites on the tree beneath the release commit. The advisory
terminal drives ran six times during this release cycle. The last run,
35547111356, passed 74 of 77 suites; the remaining three are recorded on
the 1.0.0-beta.17 page. The release job built, signed and published four
archives (linux-x64, macos-arm64, macos-x64, windows-x64) and SHA256SUMS.txt.

## What changed

- Anthropic sign-in now confirms which account signed in. The account comes
  from the sign-in result and is stored when the credential is saved. The
  Logins card, boot screen chip, `/status` and stored account update
  immediately, without needing to open `/accounts`.
- The Edit tool writes files with no known language byte for byte. Only
  prose (Markdown, plain text, AsciiDoc) keeps typographic quotes. Files
  without an extension, dotfiles and suffixes outside the highlighter's
  registry preserve the bytes the model sent.
- If the session has read a file's current version, Edit can change unread
  lines in one call. The result includes the edited lines with fresh
  anchors. A file the session has never read still requires a read first.
  Refusals start by explaining what to do next.
- Pasted text chips now store a hash of their bytes at paste time. Sending
  a message resolves each chip from the store and identifies any chip whose
  bytes are missing. Drafts over budget keep chips as references. The paste
  sweep retains anything still referenced by a draft or the history.
- Reaching a usage cap during a session turn now opens the failover offer
  card and marks the affected provider's row. The runner sends its window
  verdict through the session facts to the cockpit, which merges it into
  the single latch the card reads.
- The rail's context figure clears its published-window marker as soon as
  the session's runner fetches the live model list. Opening the picker is
  no longer required.
- The compact chat's mode chip and the full cockpit's mode band appear
  from a new chat's first frame. Chats opened from the boot screen or board
  keep their initial model, effort and mode until their session facts
  arrive.
- A new Gemini chat no longer reports "no credential" when the model
  catalogue rejects a stored Google account or API key. The error names
  the credential source, the returned status and how to recover.
- Pressing x twice on a running sub-agent's crew-board row now stops named
  teammates as well as dispatched sub-agents. The result says applied only
  after the row has ended; otherwise, it explains why the stop was refused.
  TaskStop accepts a teammate's name or full id.
- The shell result's note about scrubbed session variables appears once
  per session and again after context compaction. Otherwise, a short note
  appears only when a command names one of those variables.
- THEMIS allows read-only `git config` queries for the hooks path. Its
  blocklist matches command words and ignores text written to a file by
  a heredoc or quoted string.
- Every daemon log line includes an ISO timestamp.
- The cache-clock record is saved beside the session transcript. This
  fixes its placement under a mirrored config-home path inside the
  projects folder.
- WebFetch uses the session's model when its summariser model is not signed
  in. If that also fails, it returns the page with a note listing what it
  tried.
- `/status` no longer closes the view and exits Mercury when `CI` is set
  without an API key environment variable. The status card treats the
  credential refusal as "no key" and displays the stored account as it
  does outside `CI`.
- Background command completions reach the agent at the next tool boundary
  during a running turn, including their notification frame on the wire.
  Anything still undelivered is read at the end of the turn, without
  waiting for your next message.
- A new chat can start even when its saved default model's family has no
  usable credential. It uses the most recently signed-in family and shows
  one warning naming the saved family, the reason, the fallback family and
  how to switch back. Using `/model` in that chat saves a new default for
  the next New Session.
- Gemini picker errors name the credential source and HTTP status, with
  the remedy in a separate segment. The debug log records one masked line
  for each refused catalogue read.
- Stored Gemini keys matching the test fixture are labelled as test keys
  on the Logins card and `/accounts`, with a key hint to remove them.
  Mercury's checks can no longer write test keys into a real store.
- Opening Mercury while its previous daemon is shutting down no longer
  waits up to thirty seconds before failing. The daemon marks its record
  as stopping when shutdown starts. The new window starts a daemon as soon
  as the old one exits, so two daemons never share one config home.
- When a background completion and your message are both waiting at the
  end of a turn, your message starts the next turn. The completion is read
  within it and no longer gets a separate turn first.
- Confirmed failovers keep their note and strip marker. The session facts
  published after a model switch now name the switched model. This stops
  the cockpit from mistaking stale facts for a return to the original
  model and clearing the failover indicators.
- The model picker opens immediately with its cached GPT rows and refreshes
  them in the background. Changed rows update in place with a one-line
  notice. The selection follows its model if rows move, and a minutes-old
  list no longer goes unchecked.
- Agents can send messages in both directions between a background
  sub-agent and its main agent. Like background command completions, these
  arrive at the receiver's next tool boundary or the end of its turn. A
  message starts a turn if the receiver is idle. Each includes a
  notification frame on the wire and a receipt confirming when it is read.
- Gemini chats work with Google account sign-in again. Google's
  OpenAI-compatibility endpoint rejects account tokens that its native
  endpoint accepts. Chats using a Google account now use the native
  generation call, with streaming, tool calls, usage and the context
  ceiling preserved. Google's thought signatures are retained across tool
  rounds and resumes. Gemini API keys still use the compatibility
  endpoint. Errors now include Google's reason: the shared error reader
  expected an object, but Google returns an array, which left only
  "HTTP 401" visible. Quota errors for Google sign-in explain what to do.
- **Gemini sign-in includes setup instructions.** The card offers an API
  key first, opening the AI Studio key page and accepting one paste.
  Google account setup has six numbered steps, each opening the relevant
  Google Cloud Console page: choose the project, enable the Gemini API,
  add your address as a test user in the consent screen's audience, create
  a desktop OAuth client, paste and save the client id, then sign in
  through the browser past the unverified-app screen. Failed sign-ins
  return to the relevant step. A saved client id skips to the last step.
  The Boot face's Logins row uses the same wording. The Console addresses
  are dated, and the release-day check fetches each one and fails on a
  dead page.
- **Busy Gemini requests retry automatically.** When Google reports that
  the model is busy, Mercury retries after 1, 2, 4, 8, 16 and 30 seconds,
  about a minute in total. No notice appears for the first thirty seconds.
  After that, the retry line shows the actual wait and attempt. If retries
  are exhausted, one red error shows the attempt count and elapsed time,
  followed by Google's message. A successful retry shows one line above
  the answer. Escape cancels a wait immediately. Other providers keep
  their current single retry. All providers show "Retrying now…" when
  the countdown reaches zero.
- GPT sessions now choose helper models from the account's live list.
  Chat titles, away summaries, tool summaries, state reads, the feedback
  card, date parsing and web-fetch summaries previously used a hard-coded
  helper model that OpenAI had retired. Mercury's own check rejected it
  before any call. The helper tier now uses the cheapest available text
  model; the hook agent's tier uses the newest available plain model below
  the frontier. Neither selects an id missing from the live list. If no
  suitable model is listed, the session's model handles the request.
  WebFetch treats a summariser refusal as a failed attempt and tries the
  session's model, rather than returning the refusal as a summary. A
  release-day check compares every hard-coded model id with the live lists
  accessible to signed-in credentials. The coordinator picker marks
  remembered or configured models missing from the live list as not in
  the catalogue.
- The doctor's new "Mercury processes" row counts running and stale
  processes, those that cannot be stopped, and non-Mercury processes. Each stale entry shows its pid,
  terminal, age and reason. "Review stale processes" shows the list and
  asks for confirmation before ending them. A process stuck in a kernel
  wait is reported as "cannot end — needs a reboot"; it is never reported
  as ended. Boot only reads and records process information. Staleness
  checks use Mercury's records of live terminals, live sessions and live
  windows behind daemons. A parent pid alone is insufficient, so another running
  Mercury is never ended. Probes never open a terminal device. The same
  check runs headless as mercury doctor processes, with --end-stale after
  review.
- Moonshot sign-in now uses the provider's live model list for its default
  model and picker rows. Previously, a hard-coded table was used without
  fetching the list, so a retired model could cause a chat to fail without
  an explanation. This was the same issue that gave GPT side jobs a
  retired model id. A catalogue reader now uses Moonshot's documented
  models endpoint for the default, picker and dispatch adapter. Models
  absent from a fetched list are rejected before the call, using the
  catalogue's wording and the same handling as GPT. The hard-coded table
  is used only until a list has been fetched and shows its date. Three
  retired GPT ids were removed from the table. Z.AI has no documented
  models endpoint, so it keeps a dated table and returns the provider's
  reason for unknown-model errors. A census check rejects hard-coded
  tables used for model selection without a live check.
- **The doctor checks hard-coded model ids against live lists.** Its Model
  lists row shows the live list fetched by this process for each family
  and the ids Mercury includes. It warns by name about ids missing from
  the list. Families whose lists have not been fetched say so and explain
  how to fetch them. Moonshot uses the account's cached list, as the others
  do. Z.AI publishes no model list, so its ids are checked against the
  dated table. The release-day check probes each with one minimal
  completion only when `--probe-by-completion` is set. It sends nothing
  when the switch disabling all catalogue traffic is set. The DeepSeek
  and Moonshot list readers report non-JSON responses and unreachable
  endpoints in one sentence each, including the cause's code.
- The process sweep now supports Windows. It reads every process through
  the system's management interface, including its real executable,
  arguments, creation time and session. Mercury entries also include the
  owning account and terminal facts. Unknown results never authorise a
  stop. Immediately before stopping a process, the sweep rechecks its
  identity and terminal, then stops that process only. It uses a forced
  stop only when Windows provides no graceful option. Testing on a real
  Windows machine identified a daemon with a live owner as running and
  ended exactly the three stale processes out of six staged processes.
  The test census covers every driver on Windows. Windows testing also
  fixed the capture config's encoding and its wait for the composer row,
  allowed a bare git config query for the hooks path when another command
  follows, added the source and remedy to unreachable Gemini catalogue
  errors, and fixed reading the rail's context row after the picker closes.
- Recovered stream cuts now show one line. If a provider closes the
  connection mid-answer, Mercury makes one bounded continuation attempt.
  On recovery, the chat shows "Continued after 1 stream cut · context
  sent again" in the collapsed tool-row style. This replaces the red error
  card, warning and replayed-turn note. Expanding it shows the provider
  route, response and code. The red card appears only if recovery is
  exhausted or refused. Every cut still writes its diagnostic details to
  the debug log.
- Two lines typed in succession behind a finished background command
  now share one turn, with the command's notice read inside it. The notice
  no longer gets a separate turn between the lines. A shell line still
  ends the batch.
