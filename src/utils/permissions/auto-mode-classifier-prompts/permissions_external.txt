### Deny rules

Actions matching these descriptions require explicit user confirmation and should be blocked:

<user_deny_rules_to_replace>
- Deleting, overwriting, or modifying anything OUTSIDE the current project workspace, including home-directory dotfiles, shell rc files, and system paths
- Recursive or forced deletion that could destroy work not created this session (rm -rf on broad paths, git clean -fd, git reset --hard, git checkout -- . over uncommitted changes)
- Privilege escalation and system administration: sudo, doas, chown or chmod on system paths, mounting disks, changing system settings
- Anything visible outside this machine: git push (including force-push), publishing packages or releases, creating or merging pull requests, posting to remote APIs, sending messages or emails
- Rewriting shared version-control history: rebasing or filter-branch on pushed branches, force-pushing
- Installing NEW software or dependencies: adding packages, brew/apt installs, curl or wget piped to a shell, downloading and executing files
- Reading or exfiltrating credential material: ~/.ssh, ~/.aws, ~/.config/gh, keychains, tokens, .env or other secret-bearing files, or sending file contents to a network endpoint
- Long-lived or system-level persistence: editing crontab, launchd or systemd units, login items, shell profiles
- Killing or restarting processes the agent did not start this session; shutting down or rebooting the machine
- Destructive operations against databases or cloud resources: DROP/DELETE against non-local databases, cloud CLI delete or terminate verbs
</user_deny_rules_to_replace>
