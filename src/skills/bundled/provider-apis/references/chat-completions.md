# Shared runtime and family-specific wires

Source map read 2026-10-26. All paths in the table are relative to `src/services/providers/` unless prefixed with `src/`. These are owners to open, not a claim that every account uses one dialect.

`openaicompat/compatChatCallModel.ts` owns the shared call-model runtime. `openaicompat/compatChatClient.ts` owns Chat Completions HTTP/SSE and the `CompatStreamEvent`/`CompatFault` contracts over the HTTP/1.1 dispatcher (`allowH2: false` in `src/utils/proxy.ts` and `src/utils/mtls.ts`). `openaicompat/compatWire.ts` and `openaicompat/compatEffort.ts` build family extras and effort vocabularies. `zai/zaiCodec.ts` maps shared chat messages and tools. `src/utils/messages/apiPlan.ts` (`requestConversationPlan`, `mergeAdjacentUsers`) merges consecutive user text rows only across a turn cut (`src/utils/messages/turnCut.ts`) so the operator's ask stays its own verbatim last message while resume text stays separate from tool results, and `toolEconomy.ts` plus `src/utils/attachments/toolSchemaDelta.ts` keep the rendered tool roster stable across restarts and MCP `list_changed` updates. Preserve role-labelled messages, nested function tools and `tool_call_id` correlation.

## Stream contract

The shared transport emits `served-model`, `reasoning-delta`, `text-delta`, `tool-call-fragment`, `usage`, `finish` and `stream-fault` (`gemini/geminiClient.ts` also emits `reasoning-withheld` for omitted signed thinking). Tool fragments are index-keyed and accumulate once. `finish` preserves the raw provider reason; an unknown reason stays observable rather than becoming a fabricated truncation.

Faults carry a typed kind, code, provider words, retryability and optional status/wait facts. In-stream errors can follow HTTP 200. Missing finish/terminal data and malformed tool calls remain failures even when text arrived. `toolCallGate.ts` gates every tool call before execution across `openaicompat/compatChatCallModel.ts`, `zai/zaiCallModel.ts` and `gemini/geminiCallModel.ts`: a refusal with a pairable call ID and tool name (`schema`, `unknown-tool`, `invalid-json`, `not-an-object` in `refusalAnswersAsToolResult`) is answered by an error `tool_result` (`role: "tool"` on Chat Completions or `functionResponse` on Gemini) on the next request instead of dropping the turn, while an unpairable refusal (`missing-id`, `duplicate-id`, `provider-malformed`, including Gemini `MALFORMED_FUNCTION_CALL`) settles as a visible refusal note handed to the model on its next user turn. The runtime settles received content and reports the fault; do not discard either.

`streamIdleBudget.ts` owns `RequestWaitV1`. Wait notifications are separate from stream deltas and terminal faults. Respect the provider's explicit retry wait first; a usage/reset observation remains a displayed fact. Preserve effort and supported reasoning replay on continuation, with no thinking-time guard.

Open `scripts/provider-compat/prove-compat-chat-transport.ts` for injected-fetch SSE cases, pathological chunking, tool fragments, usage spellings and error envelopes. Use the appropriate loopback route proof as well: testing the decoder alone does not prove dispatch, auth refresh or settlement.
