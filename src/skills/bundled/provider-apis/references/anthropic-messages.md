# Anthropic Messages in Mercury

Source map read 2026-10-26. These are checkout paths; vendor links are in `live-sources.md` and must be checked for the account and date of the change.

## Owners

- `src/services/providers/anthropic/streamCore.ts` builds and consumes the streaming Messages call (`POST /v1/messages`). `src/services/api/client.ts` constructs Mercury's `AnthropicClient` (`src/services/providers/anthropic/anthropicClient.ts`, backed by `src/services/providers/anthropic/anthropicStream.ts` and `src/services/providers/anthropic/anthropicWire.ts`) over the HTTP/1.1 dispatcher (`allowH2: false` in `src/utils/proxy.ts` and `src/utils/mtls.ts`); keep that client on the Anthropic transport rather than introducing it into other families' HTTP roads.
- `/logins` offers three Anthropic sign-in roads (`src/services/providers/anthropic/anthropicLogin.ts`, `src/utils/auth.ts`): subscription OAuth (`oauth-2025-04-20`), Console OAuth that mints an API key, and a pasted API key. An organisation-scoped key (`sk-ant-usr-…` at Organization scope) is refused by the API unless `anthropic-workspace-id` (`wrkspc_…`) is sent, so `src/services/providers/anthropic/anthropicWorkspace.ts` (`needsAnthropicWorkspace`) and `src/utils/auth.ts` (`saveApiKey`, `getAnthropicApiKeyWorkspaceId`, `anthropicApiKeyHeaders`) record the workspace with the key and stamp `anthropic-workspace-id` on every Messages (`src/services/api/client.ts`), token-count (`src/services/providers/anthropic/anthropicClient.ts`), auth-header (`src/utils/http.ts`) and catalogue (`src/services/providers/anthropic/anthropicCatalogue.ts`) request.
- A slot switch (`src/services/providers/slotSwitch.ts`, `writeAnthropicPreferredSource` in `src/utils/auth.ts`) applies to new requests only: `AnthropicClient` snapshots `subscriptionAuth` at construction (`src/services/api/client.ts`, `src/services/providers/anthropic/anthropicClient.ts`) so an in-flight request keeps its credential and beta headers, and `src/services/api/withRetry.ts` recovers on a racing 401 by re-resolving `getClient()`.
- `src/services/providers/anthropic/requestParams.ts` owns extra-body assembly, model beta selection, `output_config.effort` (`low`, `medium`, `high`, `xhigh`, `max`) and cache-lifetime decisions. `src/services/providers/anthropic/cacheAndUsage.ts` owns cache-breakpoint placement, system-block assembly and usage folds.
- `src/services/providers/anthropic/messageParams.ts` maps content blocks. `src/services/providers/anthropic/thinkingBinding.ts`, `src/services/providers/anthropic/thinkingDisplay.ts`, `src/services/providers/anthropic/boundPrefixRecord.ts` and `src/services/providers/anthropic/prefixLedger.ts` own signed `thinking` (`signature`) and `redacted_thinking` (`data`) blocks, `thinking.display` (`summarized` or `omitted`; the API also documents beta `updates`), and the prefix they belong to. `src/services/providers/toolEconomy.ts` (`armToolRosterRestore`, `seedRosterLatchFromRestore`) replays the recorded tool roster across a restart or resume onto a new build so the bound prefix holds and signed thinking survives; when an MCP server's tools change (`notifications/tools/list_changed` or `/mcp reconnect`), `src/utils/toolSchemaCache.ts` gives an unreferenced deferred tool the live schema and `src/utils/attachments/toolSchemaDelta.ts` emits a `tool_schema_delta` attachment for a bound tool without moving the bound prefix. Read these before changing history replay or a cached prefix.
- `src/services/providers/anthropic/anthropicUsageState.ts` refreshes subscription usage; `src/services/anthropicLimits.ts` owns observed windows. `src/services/providers/providerUsage.ts` presents those facts alongside session spend. Usage is information, not a dispatch lock.

## Request and settlement

Follow the actual `beta.messages.create` call: model, `max_tokens`, `system` blocks, `messages`, `tools`, `thinking` (`{ type: "adaptive", display }` on adaptive models, `{ type: "between_tools" }` where supported, `{ type: "enabled", budget_tokens }` on legacy extended-thinking models, or `{ type: "disabled" }` when the model allows turning thinking off; always-on models omit `thinking` when thinking is switched off so adaptive thinking still runs) and `output_config` (`effort`, `format`) are assembled by Mercury. Preserve `tool_use`/`tool_result` pairing by `tool_use_id`. `src/services/providers/toolCallGate.ts` gates every `tool_use` block before execution: a malformed call with a pairable ID and tool name (`schema`, `unknown-tool`, `invalid-json`, `not-an-object` in `refusalAnswersAsToolResult`) is answered by an `is_error: true` `tool_result` on the next request instead of dropping the turn, while an unpairable call (`missing-id`, `duplicate-id`, `provider-malformed`) settles as a visible refusal note handed to the model on its next user turn. `src/utils/messages/apiPlan.ts` (`mergeAdjacentUsers`) merges consecutive user text rows only across a turn cut (`src/utils/messages/turnCut.ts`) so the operator's ask stays its own verbatim last message while resume text stays separate from tool results. Preserve content-block arrays and the signed-thinking binding; text serialization is not interchangeable with replaying those blocks.

Streaming (`stream: true`) emits `message_start` (carrying `input_transformations` under `thinking-binding-controls-2026-08-01`), indexed `content_block_start` / `content_block_delta` (`text_delta`, `input_json_delta`, `thinking_delta`, `signature_delta`) / `content_block_stop`, `message_delta` (whose `usage` token counts are cumulative) and `message_stop`, plus `ping` and in-stream `error` events (such as `overloaded_error`, equivalent to HTTP 529). When the headers/body or first-byte budget expires, `src/services/providers/anthropic/anthropicClient.ts` and `src/services/providers/anthropic/streamCore.ts` stamp `requestDeadline: true` onto `APIConnectionTimeoutError`, and `src/services/api/reconnectLadder.ts` (`outageCauseOf`) ignores `requestDeadline` errors so a request-deadline expiry never borrows an earlier `connect-timeout` from the transport diagnostics ring.

Read the current cache placement before editing it: the conversation has one message-level breakpoint, and the system prefix has its own cacheable blocks (`cache_control: { type: "ephemeral", ttl?: "5m" | "1h" }`; up to 4 explicit breakpoints across `tools`, `system`, and `messages`, with a 20-block lookback window, alongside the API's top-level automatic `cache_control` option). The cache clock chooses the eligible lifetime. A retry is another request, not a guaranteed cheap continuation. Keep `cache_read_input_tokens`, `cache_creation_input_tokens` (`ephemeral_5m_input_tokens`, `ephemeral_1h_input_tokens`) and uncached `input_tokens` distinct; stream usage updates replace the matching counters while cross-turn settlement accumulates them.

## Subscription client contract

`src/constants/oauth.ts` owns `ANTHROPIC_CLIENT_CONTRACT_VERSION` and `ANTHROPIC_CLIENT_CONTRACT_AS_OF`. This is contract data for the subscription endpoint, not Mercury's version or user-agent identity. A release-day change reads the vendor CLI's published version, updates the contract data if needed, stamps the check date and runs `scripts/ops/prove-client-contract-clock.ts`. Do not advance the date without that reading.

Use `scripts/api/authRetryFixture.ts` for authentication recovery and `scripts/lib/fixtureApi.ts` for captured Messages requests. Cache and replay changes also need the dialect and prefix proofs named in `proof-road.md`.
