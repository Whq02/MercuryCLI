# Native provider/account notes

Paths below are relative to `src/services/providers/` (code map 2026-10-26 unless stamped newer; vendor URLs in `live-sources.md`).

- **Moonshot / Kimi** (`moonshot/moonshotCallModel.ts`, `moonshot/moonshotAccounts.ts`, `openaicompat/compatWire.ts`, `openaicompat/kimiReplay.ts`, `moonshot/moonshotUsageState.ts`): API keys and regional coding sign-ins bind distinct endpoints. K3 always thinks, omits `temperature`, and sends effort + `max_completion_tokens`; K2.x uses `thinking` + `keep`. Preserved Thinking replays `reasoning_content`; dynamic tool declarations ride a contentless system row with `tools`; cache counters sit under `usage.prompt_tokens_details`. Usage separates API-key balance from coding windows/Extra Usage (private subscription fields are CODE contracts).
- **DeepSeek** (`deepseek/deepseekCallModel.ts`, `openaicompat/compatWire.ts`, `deepseek/deepseekUsageState.ts`): thinking toggle, effort only when thinking, `max_tokens`, streamed usage with cache hit/miss counters, and account balance reader. Stripping historical `reasoning_content` is Mercury policy (**UNRESOLVED** externally).
- **xAI** (`xai/xaiCallModel.ts`, `xai/xaiResponsesTransport.ts`, `xai/xaiUsageState.ts`): API keys use shared chat (reconciling reasoning tokens outside `completion_tokens` via `total - input` and preserving `cost_in_usd_ticks`); subscriptions use Responses. Usage separates subscription credit from optional management-key console meters (**UNRESOLVED** private quota fields).
- **Meta** (`meta/metaCallModel.ts`, `meta/metaAccounts.ts`, `meta/metaLogin.ts`, `meta/metaUsageState.ts`): no readable/replayed reasoning; model-dependent effort (`max` on Standard Spark, not Contributor; `none` refused); `json_schema` structured output; device sign-in (`subs_tier_name`/`subs_usage` shape **UNRESOLVED** publicly).
- **Z.AI** (`zai/zaiCallModel.ts`, `zai/zaiClient.ts`, `zai/zaiCodec.ts`, `zai/zaiUsageState.ts`): native chat codec (not Anthropic compat); separate General vs Coding Plan endpoints; model-specific thinking/clear-thinking, effort and tool streaming; coding windows and MCP quota (private fields CODE-owned).
- **Gemini** (`gemini/geminiCallModel.ts`, `gemini/geminiClient.ts`, `gemini/geminiCodec.ts`, `gemini/geminiPlanQuota.ts`, `gemini/geminiUsageState.ts`): API-key, OAuth and Google-plan roads preserve native signed parts via `generateContent` (not OpenAI compat), emitting trailing empty thought-signature parts as withheld reasoning before answer text so `stop_reason` lands on the answer. Code Assist quota fields and exhaustive no-usage-API claims remain **UNRESOLVED** publicly.
- **Mistral** (**CODE inspected 2026-11-13**, **LIVE page read 2026-11-04** [Mistral reasoning](https://docs.mistral.ai/studio/conversations/reasoning)): `mistral/mistralCallModel.ts` (`buildMistralExtras`), `mistral/mistralCatalogue.ts`, `mistral/mistralPins.ts`, `mistral/mistralUsageState.ts`. Effort is model-specific (e.g. hosted GLM 5.3 supports `low`/`high`/`max` without `none`; Large 4 has its own ladder): thinking off sends `none` only when supported, else the first supported effort, omitting `reasoning_effort` when unsupported. `openaicompat/compatChatClient.ts` decodes thinking/text chunks; optional Admin API usage keys stay separate from inference keys.
- **Qwen** (`qwen/qwenCallModel.ts`, `qwen/qwenAccounts.ts`, `qwen/qwenPins.ts`, `qwen/qwenUsageState.ts`): keep bound region/plan/workspace endpoints; thinking, preserved history, budget vs effort and dynamic tool-result declarations follow the profile; usage reports session spend + region/plan (**UNRESOLVED** whether key-balance APIs exist).
- **MiniMax** (`minimax/minimaxCallModel.ts`, `minimax/minimaxPins.ts`, `minimax/minimaxUsageState.ts`): `reasoning_split` with replayed reasoning; toggle models use adaptive/disabled thinking while tunable models use effort without `none`; classify `base_resp` auth/balance/rate errors even on HTTP 200; token-plan windows + session spend (**UNRESOLVED** private PAYG/M-Plan endpoints).
- **Cohere** (`cohere/cohereCallModel.ts`, `cohere/cohereAccounts.ts`, `cohere/coherePins.ts`, `providerUsage.ts`): `high`/`none` compatibility toggle, `json_object` with schema, no unsupported parallel-tool controls, session spend (**UNRESOLVED** org billing APIs).
