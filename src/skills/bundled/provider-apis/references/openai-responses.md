# Responses roads in Mercury

Source map read 2026-10-26. Vendor pages are indexed in `live-sources.md`; an OpenAI-shaped request does not establish which account endpoint serves it.

## OpenAI

- `src/services/providers/openai/openaiCallModel.ts` owns call-model integration and settlement (`POST /v1/responses`). `src/services/providers/openai/openaiClient.ts` owns HTTP over the HTTP/1.1 dispatcher (`allowH2: false` in `src/utils/proxy.ts` and `src/utils/mtls.ts`). `src/services/providers/openai/openaiWire.ts` owns typed request items, the Responses SSE stream fold and fault mapping.
- `src/services/providers/openai/responsesBridge.ts` owns request construction and ordered stateless replay. Keep `store:false`, `include: ["reasoning.encrypted_content"]` (stateless mode also returns `encrypted_content` on `reasoning` output items by default), `reasoning.effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` per the model's supported vocabulary; `reasoning.context` `auto` / `current_turn` / `all_turns`, `reasoning.mode` `standard` / `pro`, and `configuration_update` input items where applicable), `max_output_tokens`, assistant `phase` (`commentary` or `final_answer`), `prompt_cache_key`, `prompt_cache_retention` (`in_memory` or `24h` on earlier models) or `prompt_cache_options` (`mode: "explicit" | "implicit"`, `ttl: "30m" | "12h"`, `prewarm`) / per-block `prompt_cache_breakpoint`, and `function_call` / `function_call_output` correlation by `call_id`. Tools are flat function objects (`{ type: "function", name, description, parameters, strict }`), not Chat Completions' nested `function` objects. `src/services/providers/toolEconomy.ts` and `src/utils/attachments/toolSchemaDelta.ts` keep the rendered tool roster stable across restarts and MCP `list_changed` / `/mcp reconnect` updates.
- Replay captured output items (`reasoning`, `message`, `function_call`) in their recorded order. A turn without a usable record derives text and tool items from Mercury's content blocks; another provider's thinking is not an OpenAI replay item. `src/utils/messages/apiPlan.ts` (`requestConversationPlan`, `mergeAdjacentUsers`) merges consecutive user text rows only across a turn cut (`src/utils/messages/turnCut.ts`), so the operator's ask stays its own verbatim last `user` item in `input` while resume text stays separate from `function_call_output` items. Do not substitute `previous_response_id` storage for the stateless contract.
- A tool call settles once from its done item, with accumulated arguments available when the item omits them. `src/services/providers/toolCallGate.ts` gates every call before execution: a malformed call with a pairable call ID and tool name (`schema`, `unknown-tool`, `invalid-json`, `not-an-object` in `refusalAnswersAsToolResult`) is answered by an error `tool_result` (`function_call_output` on the next request) instead of dropping the turn, while an unpairable call (`missing-id`, `duplicate-id`, `provider-malformed`) settles as a visible refusal note handed to the model on its next user turn. Unknown items remain observable; a missing `response.completed` / `response.failed` / `response.incomplete` terminal event cannot masquerade as success. Usage settles from `usage.input_tokens`, `usage.input_tokens_details.cached_tokens` (and `cache_write_tokens` where reported), `usage.output_tokens`, and `usage.output_tokens_details.reasoning_tokens`.
- `src/services/providers/openai/openaiUsageState.ts` exposes the subscription usage reader and response-header band observations; `src/services/providers/openai/openaiLimitState.ts` holds the observed refusal. `src/services/providers/providerUsage.ts` presents windows, credits and spend. A recorded window is not permission to refuse the next request.

## OpenRouter

`src/services/providers/openrouter/openrouterCallModel.ts` selects the family profile. Read `src/services/providers/openrouter/openrouterResponsesTransport.ts` rather than assuming this road is always Chat Completions: it builds stateless `POST /api/v1/responses` input (`store: true` and `previous_response_id` are rejected with HTTP 400 on OpenRouter), folds events back into the shared stream vocabulary and records replay items. `src/services/providers/openrouter/openrouterCache.ts` attaches top-level `cache_control: { type: "ephemeral" }` on Responses requests for `anthropic/` models (`openrouterResponsesCache`) and explicit block `cache_control` breakpoints on Chat Completions requests for `anthropic/` and explicit-cache `qwen/` models.

Its mixed-upstream recovery is narrow: a matching HTTP 400 about encrypted reasoning from multiple providers earns one replay after removing only encrypted reasoning input items. Text, function calls, outputs and their ordering remain. Other 400s do not take that road, and a second refusal is the answer. `scripts/provider-compat/prove-openrouter-mixed-upstream-retry.ts` captures the two request bodies over loopback.

`src/services/providers/openrouter/openrouterRoutingPolicy.ts` maps `routing.openrouter` to `provider` preferences: data collection denied (`data_collection: "deny"`) and `require_parameters: true` enabled by default, with explicit fallback (`allow_fallbacks`) and zero-data-retention (`zdr`) settings preserved. Upstream routing preferences are not permission for Mercury to switch account families after a fault.

`src/services/providers/openrouter/openrouterUsageState.ts` reads `GET /api/v1/key` (`limit_remaining`, `budgets`, `effective_budget`, `free_model_daily_requests`) and classifies `402`/`403` `error.metadata.limit_source` (`openrouter_in_flight_budget`, `openrouter_key_limit`, `openrouter_credits`, `openrouter_guardrail_budget`, `openrouter_workspace_budget`). The current reader, the active key and the observation's freshness must agree before painting a balance; none of those readings closes the request door.

## xAI subscription variant

`src/services/providers/xai/xaiCallModel.ts` selects `src/services/providers/xai/xaiResponsesTransport.ts` for the Grok subscription road (`https://cli-chat-proxy.grok.com/v1`); the API-key road uses shared chat (`https://api.x.ai/v1/chat/completions`). Inspect that selector and the credential's endpoint before changing a request. Its usage owners are listed in `chat-completions.md`.

## OpenCode Zen Responses rows and custom `compat/` Responses

- `src/services/providers/zen/zenCallModel.ts` selects `src/services/providers/zen/zenResponsesTransport.ts` for the models OpenCode Zen serves only on its Responses wire (GPT, Grok and Muse rows in `src/services/providers/zen/zenPins.ts`), sending `store: false`, `include: ["reasoning.encrypted_content"]`, and the `x-opencode-session` header to `POST https://opencode.ai/zen/v1/responses` (the vendor's `https://opencode.ai/docs/zen/` page now also lists `/inference/openai/v1/responses` under "OpenCode Console"). Zen's remaining rows use `POST https://opencode.ai/zen/v1/chat/completions` (`chat-completions.md`).
- `src/services/providers/openaicompat/compatCallModel.ts` selects `src/services/providers/openaicompat/compatResponsesTransport.ts` when a custom `compat/` endpoint is configured or probed (`src/services/providers/openaicompat/compatProbe.ts`) with `dialect: "responses"`.
